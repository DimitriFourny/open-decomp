Stage 07 · Types

Types & metadata

This stage turns typed SSA plus external metadata into non-rewriting source-type constraints: associations with exact source and machine bit ranges, observed memory shapes, source signatures, and one image-wide identity for each recovered structure. It never changes the machine type of an IR value; later reconstruction and emitters decide what can be printed.

Where this sits in the pipeline

The service pipeline advances through seven named phases in src/service/analysis/index.ts: lift, ssa, metadata, types, structure, emit, and the surrounding work. At context.progress('types', 4, 7) the pipeline has a simplified SSAForm, a decoded image, resolved call references, and the two metadata recoveries it passes in: recoverDebugInfo(image, context) and recoverLibraryContracts(...). It then calls recoverTypes(ir, components.abi, fullContext, options).

recoverTypes does not merely consume a precomputed call result. It first converts supplied source signatures into AbiSignature values through SourceLayouts.abi, turns library contracts into call contracts, and then invokes analyzeCalls itself (src/analysis/types/index.ts). That call produces the stack facts and pre-effect call snapshots the rest of the stage binds against; the full CallAnalysisResult is returned in TypeRecoveryResult.calls.

The service runs type recovery up to twice. The first pass is the baseline, built from debug, library and (when applicable) Objective-C method metadata. If active annotations contain a type or signature assertion, the second pass adds the active annotation view and annotation-derived call declarations, and is restricted to subjects local to the function. A structural failure in either pass (cancelled or resource_limit) is promoted to an OperationError; no half-recovered source conclusions are published.

Later, after recoverSourceEvidence has built the source projection, the pipeline calls refineMemoryShapes with callee memory-shape transfers, then recoverImageTypes to merge compatible local views across exact pointer flows. The final types value is handed to the emitter and to semanticCatalog; the same records feed durable signatures and the function_decompile output. How the projected types become declarations, locals and casts is covered in Source reconstruction; how they are printed is covered in Structuring & emission.

Evidence, status and bit ranges

Every supplied type is a SuppliedTypeRecord carrying an ID, a structural RecoveredType definition, a source, a status, and evidence IDs. The semantic type model is deliberately small (src/core/model.ts): void, unknown, integer, float, pointer, array, vector, and structure. Arrays and structures may have null counts, sizes and alignments; those nulls mean “not established”, never “zero”.

The source set is closed and enumerated by provenance, not by an arbitrary score (src/analysis/types/model.ts): analysis, debug, library, runtime, user, llm. The service materializes debug records as debug/established, library records as library/established, and Objective-C method encodings as runtime/established. Annotation types keep the annotation's origin (user or llm) and become asserted or hypothesis. Observations built during recovery are written as analysis/candidate; durable analysis facts supplied by the project keep their own established status.

Source Produced by Default status What it can establish
debug recoverDebugInfo established Structural types, prototype signatures, source ranges and line rows
library recoverLibraryContracts established Conditional declarations for exact imports; never implementation authentication
runtime objcMethodSignature established Objective-C compiler encodings and ivar layouts
user, llm AnnotationService asserted or hypothesis Declarations in scope; never promoted to durable facts
analysis recoverTypes, refineMemoryShapes; durable project facts candidate for observations, established for durable facts Observed accesses, physical ABI fragments, inferred signedness

Status is not decorative. The reconstruction projection (src/reconstruction/source-types.ts, projectSourceTypes) admits established and asserted records, plus analysis/candidate; it rejects hypotheses and conflicting records. If any candidate for a value comes from a non-analysis established/asserted source, analysis candidates are filtered out entirely. If the remaining alternatives still denote more than one distinct definition, the value keeps no projected type. The ABI view is stricter still: SourceLayouts.definition(id, true) only considers established and asserted records, which is why a hypothesis cannot supply an aggregate layout.

There is no numeric rank among debug, library and runtime: all three are established suppliers, and a disagreement between them becomes incompatible_types rather than one source silently winning. ABI is a constraint layer, not a type source: it decides which physical bits a declaration covers and which fragments are ABI-complete, but it never invents a source type. Observed usage is the weakest layer: it supplies analysis/candidate associations; at projection time they are discarded in favour of any established/asserted non-analysis declaration.

Invariant

A source association never rewrites an IR value's machine type. TypeAssociation keeps the machine type separately (machine_type) and describes only a fragment of it. recoverTypes builds its result from immutable SSA and never mutates the input form or the supplied metadata.

The association is the unit that makes exact ranges possible (src/analysis/types/model.ts): 

export interface TypeAssociation extends TypeBinding {
  readonly id: string;
  /** Null for storage, fields and declarations; never rewrites an IR value type. */
  readonly machine_type: DataType | null;
  /** A physical ABI/register fragment is not the entire declared source object. */
  readonly value_offset_bits: number;
  /** Start of the known fragment within machine_type; independent of source offset. */
  readonly machine_offset_bits: number;
  readonly width_bits: number | null;
}

Every association carries the source and status of the binding that produced it: a debug or library declaration stays established, an annotation stays asserted or hypothesized, and an observation built by this stage stays a candidate. Propagation adds its own evidence and may downgrade a status to candidate when an edge is conditional. The three coordinates answer different questions. value_offset_bits is where the fragment starts in the source object (or the caller-relative object); machine_offset_bits is where it starts inside the machine value it came from; width_bits is the overlap actually proven. The distinction is essential when a declared value is split across registers or when a struct is passed by value. bindLocation computes the intersection of the declared ABI fragment and the observed register binding: 

const start = Math.max(register.offset_bits, binding.register.offset_bits);
const stop = Math.min(
  register.offset_bits + (width ?? register.width_bits),
  binding.register.offset_bits + binding.register.width_bits,
);
if (start >= stop) continue;
associate(
  { subject_id: binding.value.id, type_id: physicalType, /* … */ },
  offset + start - register.offset_bits,
  stop - start,
  start - binding.register.offset_bits,
);

Here offset is the declared source displacement (for example a struct field), the first computed value becomes value_offset_bits, the width is the intersection, and the last value becomes machine_offset_bits. A declaration therefore constrains only the bytes both sides actually cover. Independently, SourceLayouts.size and SourceLayouts.fields walk structures and arrays by exact byte size; they refuse a cyclic by-value graph, a missing layout, or a size that overflows 0xffff_ffff_ffff_ffff.

Type recovery as implemented

recoverTypes is one bounded pass with a deliberately conservative output contract: supplied inputs are the entire revision, not deltas, so retracting an annotation cannot leave a stale assertion in a cached result. The implementation proceeds in this order.

  1. Index values and transfer edges. Block parameters, instruction results, register outputs and call results become subjects. extract and same-width bitcast create transfer edges with offsets; select creates conditional edges; block arguments transfer into target parameters. concat operands are recorded as composition edges. A cast alone never manufactures a declaration.
  2. Add supplied definitions and signatures. Option types are added first; then debug and library types are re-stamped as established. Debug signatures are accepted only when entry_address is exactly a VA in this image. Annotations with name/note or retracted are ignored; type annotations become records and bindings, signature annotations become supplied signatures. A type anchored to the function itself declares the type in scope, not a scalar machine type for the function.
  3. Validate and route contracts. Every supplied signature whose abi differs from the target produces a conflicting_evidence warning and is skipped. Function-level declarations become function contracts; exact call-node declarations become call contracts; library contracts are added only when abi_state === 'supported'. A call-local declaration stays call-local.
  4. Run call and stack analysis. analyzeCalls receives the remaining work budget. If it returns partial, recoverTypes returns an empty partial result with the call diagnostics and publishes no source conclusions.
  5. Bind physical locations. For each contract observation, parameter and return locations are matched to pre-effect register/stack snapshots. Register fragments produce associations with the intersection arithmetic above; stack storage becomes a stackTypeSubject keyed by entry-SP-relative offset. Hidden results are modeled as a pointer to the declared return type.
  6. Group observed accesses. The affine resolver (next section) normalizes every load/store address and every indirect-call target. Accesses group by stack or by affine base; each group records fields, widths, access kinds, strides, dynamic flags, evidence, and whether the base escaped or aliased.
  7. Build shapes and candidate types. buildMemoryShape sorts fields, computes the relative origin and observed extent, names members from relative offsets, turns a stride that equals the access width into an array of unknown count, and emits analysis/candidate records. A shape whose base_offset is zero also associates the base value (and each exact pointer fragment) with a pointer to the shape type.
  8. Derive signedness from use. Float/vector operations associate their machine type. Signed division/remainder/arithmetic shift mark their operands signed; unsigned division/remainder/logical shift mark them unsigned; ordering comparisons mark operands signed. These are operation-use candidates, not rewrites of the value.
  9. Propagate. A worklist forwards each association along transfer edges whose offset and width fit inside the current fragment, translating the source offset and preserving status (conditional edges downgrade established/asserted to candidate). A second rule reassembles a concat only when every part is the exact same-typed fragment at the expected offset. The worklist identity bounds cycles.
  10. Match declared fields and detect conflicts. Non-analysis declarations at offset zero are projected onto observed fields through SourceLayouts.fields. A field that lies outside a known value-based object, or whose width contradicts a declared member, produces a layout_mismatch. Overlapping observations produce overlapping_accesses; differing declared definitions produce incompatible_types; differing signatures produce incompatible_signatures. Conflicting associations are marked conflicting and all alternatives survive.

The conflict taxonomy is small and explicit (src/analysis/types/model.ts):

reason Raised when Effect
incompatible_types Two declared alternatives at the same subject/offset/width have different canonical definitions, or one type ID has different definitions Associations become conflicting; the diagnostic names every evidence ID
incompatible_signatures More than one non-candidate signature for one subject fingerprints differently Non-hypothesis/non-candidate signatures become conflicting
overlapping_accesses Two observed fields overlap and are not the same offset/width/period view Shape keeps both fields and records the conflict
layout_mismatch An observed field falls outside a declared object, or contradicts a declared member's size Conflict on the field; the declaration is not silently reshaped

Diagnostics are warnings: conflicting_evidence for every conflict, unavailable_semantics for an out-of-scope subject or an unavailable binding, and conflicting_evidence again when a supplied signature belongs to a different ABI. Budget or cancellation failures are different: they throw through AnalysisBudget and the catch returns state: 'partial' with empty type/shape/association arrays. The default max_work for this pass and for shape refinement is 1_000_000. Per-record guards reject more than 1,000 evidence IDs, more than 10,000 structure fields, or recursion past 64 frames; integers over 512 bits become unknown, and a computed size above 0xffff_ffff_ffff_ffff stays unresolved.

Refusal

The stage refuses to guess object sizes, alignments, array counts, complete layouts, or a winner among conflicting declarations. Structures produced from observations have size: null and alignment: null; arrays produced from strided accesses have count: null. A debug aggregate without DW_AT_alignment keeps a null alignment, and the ABI view classifies it as unknown rather than inventing natural alignment.

The tests pin these behaviours directly: test/analysis/types/types.test.ts covers assertion alternatives, isolated casts not establishing types, hypothesis signatures, unknown parameter counts, overlapping widths, recursive pointers, budget exhaustion, call-local declarations, and physical fragments not attaching to arithmetic ancestors. memory-shapes.test.ts covers wrapped signed displacements, independent indices, callable field identity, parameter closure and phi views.

Memory shapes and affine addresses

An ObservedField records a signed displacement from an original base, an access width, the nodes and values that contributed, read/write use, an optional stack region, an optional proven stride, and optional call-target or index evidence. A MemoryShape groups those fields under a base that is either one SSA value or the function's stack. Its base_offset may be negative, and its observed_extent is explicitly “constant-displacement accesses only”. 

export interface MemoryShape {
  readonly base: { readonly kind: 'value'; readonly value_id: string } | { readonly kind: 'stack' };
  readonly type_id: string;
  /** Relative origin of the incomplete structure view; not a complete object boundary. */
  readonly base_offset: bigint;
  /** Constant-displacement accesses only; dynamic indices establish no extent. */
  readonly observed_extent: { readonly start: bigint; readonly end: bigint } | null;
  readonly fields: readonly ObservedField[];
  readonly alias: 'possible' | 'observed';
  readonly escape: 'unknown' | 'observed';
  readonly dynamic: boolean;
  readonly evidence_ids: readonly string[];
}

Affine address resolution

createAffineResolver (src/analysis/types/memory-shapes.ts) normalizes a 64-bit address expression into { base, offset, stride, index? }. It only follows exact, local structure:

  • Constants and add/sub with one constant addend accumulate into offset, wrapped with BigInt.asIntN(64, …). The test suite checks that repeated offsets wrap at machine width.
  • or/xor with zero and and with 0xffffffffffffffff are identities; other bitwise combinations stop resolution.
  • One scaled index (mul by a constant or shl by 0–63) yields a positive stride only in 1..65536. A second independent index is never collapsed into a guessed stride.
  • A loop-carried byte offset i = c; i += s added to an invariant base resolves to base + c + k*s, with index set only when an independent counter with initial 0 and step 1 is proven on the same edges.
  • Block parameters resolve to a common address only when every incoming affine result has the same base, offset and stride; otherwise the parameter itself becomes the base.
  • A concat resolves only when every part is an exact extract, at the expected offset, of one 64-bit value. Otherwise an identical concatenation owned elsewhere supplies the normalization.
  • extract at offset 0 and same-width bitcast preserve the address; anything else falls back to { base: value.id, offset: 0n, stride: null }.
Invariant

Offsets are signed and machine-width wrapped; a negative displacement is preserved rather than normalized to a guessed object start. base_offset is negative when the earliest observed access is below the base, and member names are still relative to the shape origin. The tests assert a negative base_offset and observed_extent for a caller-relative callee view.

Grouping, arrays and uncertainty

Loads and stores are grouped after resolution. A stack access recognized by the stack pass uses the stack group and the access's own offset; otherwise the group key is the affine base and the field offset is the affine offset. A strided access sets stride and marks the group dynamic; a load whose value is later used as an indirect call target gets call_target_ids and a pointer-to-unknown type, with no prototype or argument count implied. Stores, call register inputs and returned values mark bases as escaped; stack alias/escape/dynamic flags come from the stack frame facts.

buildMemoryShape sorts fields by offset and width, sets base_offset = min(0, first offset), and extends observed_extent only for non-dynamic constant-displacement fields. A field whose stride equals its width in bytes becomes array(element, count: null). Two overlapping fields are a overlapping_accesses conflict unless both are non-dynamic views with the same offset and width and a compatible stride. The resulting structure always has null size and alignment, and the shape's observed_extent is never used as an object size.

Parameters and refinement

parameterMemoryShapes packages the shapes whose base is an observed pointer argument: the shape, its field associations, the transitive type closure, evidence, and any related conflicts. It returns nothing for a partial recovery or zero parameters. refineMemoryShapes then folds a callee's parameter shape into a caller through one exact transfer (the call ID and the caller argument value). It computes the callee's affine address in the caller, adds the displacement to each callee field offset with signed 64-bit wrapping, imports the callee's type records (recursively through pointer, array and structure members), and keeps the callee's value IDs out of the caller's value bindings. Two independent indices make the merged field explicitly dynamic and clear its stride; no extent is invented.

Refinement is transactional. It copies the existing result, adds evidence records and diagnostics, and on any budget/cancellation failure returns the original result plus a partial state and a resource_limit diagnostic. It never reruns ABI, SSA or stack analysis, and no foreign callee value becomes a caller SSA declaration.

Worked example: two field accesses become a struct

The repository fixture gives the minimal case. Decompiling _fixture_memory in macho-arm64-symbols (entry va:0x1000005c0) produces one observed field at displacement 0 and width 64: 

uint64_t fixture_memory(uint64_t* address, uint64_t arg1) {
  uint64_t result;
  result = *address + arg1;
  *address = result;
  return result;
}

The repository fixtures contain no multi-field pointer struct, so for the struct case I compiled a small local C fixture (outside the repository) with clang -O1 -g0 -dynamiclib: 

struct point { unsigned x; unsigned y; };
struct point *make_point(struct point *p, unsigned x, unsigned y) { p->x = x; p->y = y; return p; }
unsigned sum_point(struct point *p) { return p->x + p->y; }
unsigned use_point(struct point *p) { return sum_point(p) + make_point(p, 1, 2)->x; }

The built binary reports _make_point at va:0x2f0, _sum_point at va:0x2f8, and _use_point at va:0x304. Decompiling _use_point produces: 

typedef struct use_point_arg0 use_point_arg0;
uint32_t use_point(use_point_arg0* address) {
  uint32_t value0;
  uint32_t value1;
  value0 = *(uint32_t *)(uintptr_t)address;
  value1 = *(uint32_t *)((uintptr_t)address + 4);
  *(uint64_t *)(uintptr_t)address = 0x200000001;
  return value0 + value1 + 1;
}

The type command on the same image emits the observed members:

typedef struct use_point_arg0 use_point_arg0;
/* … make_point_arg0 and sum_point_arg0 omitted … */
/* seen in use_point */
struct use_point_arg0 { uint32_t field_0x0; uint32_t field_0x4; };

The two 32-bit loads at displacements 0 and 4 establish two fields of width 32. The 64-bit store at displacement 0 is a third observed access that overlaps both; it remains a separate access and is not folded into the declaration. The header states the limits verbatim: “observed members only; sizes and complete layouts are unknown.” The struct name comes from the image-type naming rules, not from the recovered shape itself.

Image-scoped struct identity

A function-local shape cannot answer whether two functions observed the same structure. src/analysis/types/image-types.ts supplies that identity: every function contributes objects (views at displacement zero plus pointer values at exact flows), and one unification merges the views connected by those flows. The key is explicit: an image-level anchor is the value a function receives in an integer argument register, returns in its result register, or the address of one entry-SP-relative stack object.

The service's functionTypeObjects (src/service/analysis/image-types.ts) builds those objects. It keeps only shapes with a value base and base_offset === 0, skips dynamic or negative fields, classifies members by their declared analysis type (pointer, float, integer), and records pointees only for 64-bit members whose loaded value resolves exactly to another local object at displacement zero with no stride. Anchors come from integer argument registers at entry, arguments at direct calls, the result register at returns and direct calls, and stack addresses. own marks the callee side; call sites are caller-side views.

exploreImageTypes is bounded and deterministic: MAX_NEIGHBOR_FUNCTIONS = 12, MAX_CALLERS_PER_FLOW = 4, and MAX_POINTEE_DEPTH = 2. It walks the frontier breadth-first by depth then canonical key, loading bodies through the shared native-unit cache. A flow stays open if its callee body is unavailable, more callers exist than the limit, the flow was never expanded, or the image reference index is not complete. Exhaustion keeps what was explored and marks the affected classes bounded.

solveImageTypes is a union-find over object keys. Two flows unify only after the callee side confirms the value as an object (it dereferences it, has fields/pointees, or forwards it into another confirmed flow); a stale caller register alone never joins unrelated objects. Unions are accepted only when compatibleImageFields finds every cross-side overlap to be the same member (same offset, width, compatible stride, and both float or both non-float). Refused unions are recorded as mutual conflicts; the two classes keep their own layouts. Merged fields use the key offset:width:isFloat, fill a missing stride, and promote the kind to pointer when either side proved a pointer. Pointees of a merged member are queued for their own union.

Names are deterministic and evidence-ranked. An argument anchor outranks a return anchor, which outranks a caller stack slot. Names are fn_argN, fn_ret, or fn_local_hex; pointee classes without their own flow identity are named owner_foffset[e] in four deterministic rounds; anything left is fn_objN. A bounded class appends a four-hex-digit digest of the merged layout, so one name never denotes two layouts; refused-union name collisions get a numeric suffix. Class IDs are image_type_<fingerprint(members)[:24]>.

The types command and types.h

executeImageTypes in src/service/analysis/index.ts recovers metadata, loads the function index, and calls imageTypeDump with a byte bound taken from the output budget, the optional result limit, and the response frame limit. imageTypeDump gives the pass floor(remaining*3/4) work, analyzes every function body in entry order as far as the budget allows, then solves once. It filters to non-local classes with at least one observed member, renders C declarations, and halves the number of shown classes until the text fits max_bytes. The result is complete only when every function was analyzed and every class was shown; otherwise it is partial.

src/emitters/image-types.ts owns the declaration spelling. It emits observed members only, inserts explicit uint8_t pad_* arrays for byte gaps, writes void* (or a named pointer) for pointer members, adds [] only for the last member with a proven element stride, and marks a structure __attribute__((packed)) when a member is not naturally aligned in the observed layout. Sizes are never printed. A class with one scalar member at offset zero is emitted as a plain scalar pointee instead of a struct.

export BINARY --out DIR writes the same text to types.h from the first export session; the pseudocode files use the same names. Image classes bind through ImageTypeBinding (type_id, name, state, functions, conflicts), and only non-local classes appear there. A class private to one view is classified but not exported; its declaration stays local.

Debug formats: DWARF and CodeView

Debug information is the strongest structural evidence available, but it is treated as supplied bytes with an exact identity, never as a filesystem lookup. recoverDebugInfo(image, context, external?) (src/metadata/debug/index.ts) accepts only an optional host-owned ExternalDebugInput with artifact_id and optional expected SHA-256. No path is accepted; there is no source-file access, symbol-server query, or target execution.

The pipeline calls recoverDebugInfo(image, context) without external input: both executeDecompilation and executeImageTypes do. No shipped surface — CLI, MCP, BinarySession/openBinary, or either execution function — passes ExternalDebugInput. A sibling .dSYM is never discovered, and no PDB is opened. The debug evidence the pipeline can actually receive is therefore:

  • Mach-O: DWARF sections embedded in the selected slice, read from a __DWARF segment with __debug_* sections. A linked image without embedded DWARF yields absent.
  • PE: absent; CodeView is identity-only and is not wired into DWARF recovery.
  • ELF: partial with an unavailable_semantics diagnostic; debug types and signatures are not recovered.

None of the shipped Mach-O fixture binaries contains a __DWARF segment, so their CLI decompilations and types runs carry no debug types or signatures. External bytes can be parsed only by importing the root-exported recoverDebugInfo and calling it directly with an ExternalDebugInput; the returned DebugRecovery is not consumed by the decompile/types pipeline. For the fixture dSYM, such a direct call on fixtures/bin/macho-arm64-symbols.dSYM/Contents/Resources/DWARF/macho-arm64-symbols matches the image UUID 7d08d21e-2af8-3aa2-9bdc-0ea4464b5088 and yields 60 types, 17 functions with 17 signatures, 60 variables, and 161 line rows; it reports partial because some location expressions use unsupported opcodes. The recovered fixture_memory signature at va:0x1000005c0 is u64 (u64 *, u64) with parameter names p and delta.

External dSYM selection

selectDebugSections (src/metadata/debug/macho.ts) parses the target's Mach-O load commands to obtain CPU type, subtype and LC_UUID. For external bytes it accepts a thin Mach-O or a universal container, requires the target to have an LC_UUID, and keeps exactly one slice whose CPU, subtype and UUID all match. Zero matches, multiple matches, or a universal table that disagrees with its slice are conflicting_evidence. Other checks are equally strict: external content SHA-256, at most 128 MiB, no __zdebug or compressed ZLIB sections, no unresolved relocations, no zero-fill DWARF sections, no overlapping sections. Any of those either rejects the input or turns it into an explicit partial diagnosis.

DWARF sections and DIE parsing

parseDwarfSections (src/metadata/dwarf/index.ts) reads Mach-O __debug_* sections. The parser consumes __debug_info, __debug_abbrev, __debug_str, __debug_line_str, __debug_addr, __debug_str_offs, __debug_ranges, __debug_rnglists, __debug_loc, __debug_loclists, and __debug_line; it recognizes __debug_types only to diagnose that signature units are unsupported. It supports DWARF 2–5 compile/partial units, 32- and 64-bit DWARF offsets, v2–5 line programs, range lists, v2–4 location lists and v5 loclists. Split/supplementary types, compressed sections and general location evaluation are unsupported.

Unit parsing is a two-level structure. abbreviations decodes the abbreviation table (tag, children flag, and attribute name/form pairs, including implicit constants); the unit loop then reads DIEs until the unit end, maintaining a parent stack. A null code pops a parent; a non-root DIE without a parent or a second root is malformed. The root must be a compile/partial unit tag. References are resolved by absolute or unit-relative DIE offset; relative references that escape their unit are diagnosed, and inheritance through DW_AT_specification/DW_AT_abstract_origin is cycle-checked. The parser never infers a missing attribute through an unresolved link.

Structural types are built from raw DIE facts, not from display names: DW_AT_byte_size, member DW_AT_data_member_location, DW_AT_bit_size, DW_AT_data_bit_offset, array DW_AT_upper_bound/DW_AT_count and subrange children, base-type encoding, pointer size, and DW_AT_alignment when present. A structure is accepted only if every member has a known type, a byte offset, no bitfield bits, a bounded name, and fits the declared size; otherwise it becomes unknown with an unavailable_semantics diagnostic. Pointers are accepted only at 8 bytes. Arrays become nested array types whose count may be null.

Function signatures are accepted only under a known calling contract: a prototyped parameter list, or a concrete C-family definition with zero parameters and a language in the accepted set; calling convention must be absent or 1; at most 1,000 parameters. A DWARF range that is not fully file-backed in the selected image clears the signature and emits invalid_address. Two distinct definitions claiming overlapping code keep both claims, null both signatures, mark them conflicting, and link their evidence with conflicts_with.

Locations are deliberately shallow. decodeLocation (src/metadata/dwarf/location.ts) recognizes exactly one complete storage description: register, register-offset, frame-offset, absolute address, or indexed address. It rejects compound expressions and anything longer than 1,024 bytes rather than evaluating DWARF bytecode. The line program (src/metadata/dwarf/line.ts) executes the standard state machine and emits half-open address intervals; rows with no known successor have no endAddress. Variables and inline scopes are retained and can be queried with variableLocationsAt and debugContextAt, but the type stage only consumes types and function signatures.

Budget and refusal

DWARF parsing has hard limits in src/metadata/dwarf/reader.ts: dies: 100_000, depth: 128, rows: 500_000, steps: 2_000_000, string: 1_048_576, text: 64 * 1024 * 1024, plus 10,000 units and 128 MiB of sections. Exceeding a limit is a resource_limit; malformed bytes are isolated per unit where possible and become malformed_image diagnostics.

CodeView is much narrower (src/metadata/codeview/index.ts). recoverCodeViewReferences scans PE debug_record headers for RSDS and NB10 identities, normalizes the RSDS GUID's mixed-endian fields, and returns identity, conflicting, or unsupported records. The embedded PDB path is untrusted text and is never resolved, opened, or fetched. The function is exported at the package root but is not wired into recoverDebugInfo; no PDB type or symbol parsing exists, so a CodeView record contributes identity evidence but no DWARF-like types.

Library contracts and prototypes

Library metadata answers a conditional question: “if this import is the documented function from this library, what is its source interface?” It never authenticates the loaded implementation. recoverLibraryContracts (src/metadata/library-contracts/index.ts) matches imports by exact original name and nominal library identity. Weak imports and imports bound through a nonzero relocation addend are excluded and reported as unavailable_semantics; their nominal identity does not establish the callable contract. Local symbols, demangled text, ordinals, and imported pointer storage never create contracts.

There are two declaration tables. The curated catalog.ts holds 128 entries with hand-reviewed effects, memory footprints, captures, returns_argument, noreturn flags, and variadic rules. The generated table holds 6,902 function prototypes and 424 extern data objects across twelve modules. The generated entries carry interface facts only: no memory footprint is invented, so pointed memory effects remain unknown unless a curated entry says otherwise.

How the catalog is generated

scripts/generate-library-prototypes.ts runs clang -Xclang -ast-dump=json -fsyntax-only over real headers. The macOS SDK supplies ISO C, POSIX, Darwin libSystem and CoreFoundation; Homebrew mingw-w64 supplies the Windows CRT and API surface, with llvm-nm over import libraries deciding which DLL exports a name; hand-written headers under scripts/library-prototypes/ cover glibc/Itanium-ABI symbols and libc runtime support. A unit records its provenance and include roots; declarations are classified by header path and import-library membership. Parameter names missing in one SDK are borrowed from the mingw-w64 declaration only when the arity matches, or from the checked-in parameter-name table.

The emitted line format is compact and typed. A function line is name|return|parameters|flags|header; a variable line is =name|type|flags|header; a handle definition is &Name=type. Type codes use one letter per scalar (SCALAR_CODES), *T for a pointer, ^T for a pointer to const, @Name; / @!Name; for opaque types, $name; for an ABI-dependent typedef, and &Name; for a named pointer typedef. Flags carry noreturn (n), variadic (v), printf or scanf format parameter indices (f<i>, s<i>), and open-flags index (o<i>). The runtime decoder in generated/index.ts indexes a family's module on first use and caches decoded entries.

findDeclaration checks the curated entry first, but only if the import's library path identifies that entry's family for the target format; otherwise it scans LIBRARY_KINDS for a family matching the path and asks that generated table. This is why a symbol name alone is insufficient and why the same name can resolve differently on Mach-O, ELF and PE. findVariable applies the same rule to extern data objects.

From contract to types

Each matched import becomes a LibraryContract with a source Signature, an AbiSignature, noreturn, effects, a variadic rule, and a source string. recoverTypes accepts only abi_state === 'supported' contracts, turns the signature into a supplied declaration, and adds call contracts for both the import target and the callable entry when one exists. bindLocation then attaches the declared parameter and return types to the exact physical locations; import storage itself is never treated as a callable entry.

Typed imported data is separate. recoverImportBindings in src/analysis/strings/source-data.ts calls findVariable for non-weak, unadjusted imports and records only the declared type, constness and source. It records no size, array extent, layout, write or alias fact. The type spec is preserved for the emitter's source spelling (variables.ts).

A real match from the Mach-O fixture:

/* decompiled main, fixture macho-arm64-symbols; unrelated lines omitted */
extern int32_t puts(const char*);
/* … */
puts((const char*)fixture_string());

The import table names puts in /usr/lib/libSystem.B.dylib. findDeclaration('puts', …) selects the curated C entry with the standard C return int, the const char* parameter, and a read footprint for argument 0. The signature is conditional library evidence, not proof that the loaded libSystem implementation is unmodified.

Objective-C and Swift runtime metadata

On Mach-O, the runtime reader recovers static language metadata without executing the target, calling metadata accessors, or interpreting dynamic class_rw tables. recoverRuntimeMetadata (src/metadata/runtime/index.ts) first checks whether any recognized section is present. Objective-C sections are __objc_classlist, __objc_nlclslist, __objc_catlist, __objc_nlcatlist, __objc_protolist, __objc_selrefs, __objc_classrefs, __objc_superrefs, plus the non-pointer-array __objc_stubs and __cfstring. Swift sections are __swift5_types and __swift5_fieldmd. If none is present the result is absent.

RuntimeReader (src/metadata/runtime/reader.ts) keeps every read inside a declared, readable, file-backed section, refuses encrypted ranges, and treats fixups as logical pointers rather than authentication. It resolves load-command bindings and import slots so that class references and _objc_msgSend stubs can be recognized. Records are deduplicated by (kind, address, owner, name); each record and each name/reference claim gets separate analysis and binary evidence.

Runtime metadata feeds two different consumers. First, records become SymbolRecords: a class or protocol gets an object symbol, a method implementation gets a function symbol named -[Class selector] or +[Class selector], and an __objc_stubs entry gets _objc_msgSend$selector. prepareQueryImport appends these symbols before decorateImageNames and then passes the decorated image to discovery and reference indexing, so runtime names participate in function naming and stub classification. Runtime name strings remain names, never signatures.

Second, objcImageIndex (src/metadata/runtime/objc-index.ts) keys selector references, class references, stubs, strings, method implementations, selector type encodings, ivars, and superclasses by VA. The type stage calls objcMethodSignature (src/service/analysis/objc-signature.ts) only when no durable or debug signature exists. A method record whose duplicates all agree gives the compiler's type encoding; unparseable encodings, conflicting records, or an arity mismatch produce no signature. The parser (src/metadata/runtime/objc-types.ts) accepts scalar and pointer encodings, rejects aggregates, unions, arrays, bitfields, long double and unknown elements, and never invents variadic methods. For an instance method, self is a pointer to a structure built from the class's ivars and its in-image superclasses at their static offsets, using declared names and sizes.

Static limits

Runtime limits are max_records: 100_000, max_entries: 100_000, max_depth: 64, max_string_bytes: 4096, and max_total_string_bytes: 8 * 1024 * 1024. A recognized but unsupported record (realized class_rw, unknown Swift descriptor kind/version, unrecognized stub) produces an unavailable_semantics issue and a partial result, never a guessed layout. Ivar offsets are the static values this image was linked against; the runtime may slide non-fragile ivars.

Limitations & extension points

The design is intentionally conservative: a missing fact stays missing, and a contradiction stays visible. That produces several sharp edges a contributor should expect.

  • Pointer inference is incomplete. A machine value is not promoted to a pointer merely because it is used in an address computation or cast. The R4 roadmap in TODO.md lists the remaining work: propagate pointer-ness through dereference, known prototypes, allocator returns, pointer comparisons, and add/sub from a pointer across the callee-summary and image-type paths; resolve conflicts by evidence weight with a visible cast instead of dropping the type; name structures from prototype parameters, allocator size, or the shared field pattern; and render pointer arithmetic as indexing or field access when stride and base are established. None of that is implemented in this stage yet.
  • Observed extent is not object size. Shapes have null sizes and alignments. types.h deliberately omits sizes, and an array count recovered from a stride is always null.
  • Debug support is Mach-O DWARF only. The pipeline reads embedded __DWARF sections from the selected slice; ELF recovery returns partial with an unavailable_semantics diagnostic, and PE returns absent (CodeView is identity-only and not wired in). No shipped surface passes ExternalDebugInput and no sibling .dSYM is discovered; external DWARF can be parsed only by calling the root-exported recoverDebugInfo directly, and that result does not feed decompilation or types output. None of the shipped Mach-O fixtures embeds __DWARF.
  • Some DWARF is deliberately unevaluated. Compound location expressions, split/supplementary units, compressed sections and unresolved relocations are refused. Aggregates with bitfields, missing member offsets, or no alignment stay unknown/ABI-unknown rather than guessed.
  • Image merging is bounded. At most 12 neighbor bodies, 4 callers per flow and 2 pointee hops are explored. Exhaustion, an incomplete reference index, or an unavailable callee marks classes bounded; their names carry a layout digest. Only non-local classes are exported, so a private single view is absent from types.h and keeps its local spelling.
  • Annotations are not facts. Asserted and hypothesized declarations remain project-scoped alternatives. They trigger a second recovery pass but are never promoted into durable signatures or type facts, and a retraction removes their influence.
  • Library declarations are conditional. Weak and adjusted imports are refused; a matched name and library path does not authenticate the implementation. Generated prototypes carry no memory effects, so pointed-to memory stays read/write-unknown unless a curated entry supplies a footprint.

Adding a library family

  1. Add the family to LibraryKind and LIBRARY_KINDS in catalog.ts. findDeclaration iterates this list, so omission makes the generated table unreachable.
  2. Teach identifiesLibraryKind how the target format identifies that family (DLL name and optional API-set pattern for PE, soname/path for ELF, install name for Mach-O). A declaration that does not identify its family is never returned.
  3. Add a unit to scripts/generate-library-prototypes.ts (headers, include roots, provenance, classifier) or a hand header under scripts/library-prototypes/, then regenerate the data modules. Add a curated entry only when effects, footprints or variadic rules need hand review.
  4. Add tests for the positive match, a wrong-library negative, and a weak/adjusted import refusal. The generated decoder validates every type code and handle, so a malformed code fails at load rather than producing a partial layout.

Adding a debug format

  1. Produce a DebugRecovery-shaped result: structural types with stable IDs, functions with exact VAs and optional Signature values, evidence with a verified origin, and diagnostics. Do not mutate IR or synthesize alignments.
  2. Route it from recoverDebugInfo or add a sibling recovery that the service passes into recoverTypes. The type stage only understands supplied records, signatures and evidence; it does not care which format produced them.
  3. Keep identity exact. The external dSYM path rejects mismatched UUID/CPU and ambiguous slices; a new format needs an equivalent external-identity check (GUID/age for PDB, build ID for ELF) before any bytes are authoritative.
  4. Map unsupported constructs to unknown/partial with a diagnostic code from the existing set, rather than guessing. The conflict machinery will retain alternatives if the new source disagrees with debug or library evidence.
Where the code and secondary docs diverge

docs/CORE.md summarizes the same design and is consistent on the main points (non-rewriting associations, exact bit ranges, image identity, bounded exploration). The code additionally shows that no shipped surface passes external debug input, that a sibling dSYM is never discovered, and that CodeView is identity-only; the secondary text is easy to read as if debug types were always available.
