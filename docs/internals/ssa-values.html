SSA, values & stack

The lifted register IR is turned into SSA over architectural register cells, the SSA graph is folded and rewritten, and a separate interpreter tracks the machine stack byte by byte. The output is a small, explicit data-flow graph plus stack facts that the call, type and reconstruction stages consume.

Where this sits in the pipeline

The lifter (page Decoding, lifting & IR) hands over a RegisterIR: basic blocks whose instructions still read and write RegisterDescriptors explicitly through read_register and write_register nodes, and whose terminator edges carry no data arguments. This stage produces two things. First an SSAForm, where architectural state is a set of frozen register cells, every cell reference resolves to a single dominating definition, values that meet at joins are passed as block parameters and edge arguments, and loads, stores and calls carry full register snapshots. Second a set of stack facts, produced by a separate non-rewriting interpreter that treats the SSA graph as its program.

The split is deliberate. SSAConstruction in the IR contract says it directly: construction and optimization are separate passes, and “no SSA algorithm is hidden in the lifter” (src/ir/model.ts, SSAConstruction). The service layer runs the same chain for a normal decompilation: lifter.lift, abiObservableRegisterMasks, constructSSA, simplifySSA, each gated by requirePass and measured by boundIR (src/service/analysis/index.ts, passOptions). Stack recovery is not called there directly; it is the first thing analyzeCalls does, and the remaining call-analysis work is charged against what stack recovery left of the same budget (src/analysis/calls/index.ts, analyzeCalls).

SSA construction is used in one more place: native dependency preparation calls constructSSA and simplifySSA with a local ssaLimit, and if only that local limit is exceeded it returns a partial preparation with ir: null and a reason string instead of failing the caller (src/service/analysis/native-prepare.ts). specializeNativeSSA also synthesizes an entry block with constant bindings and runs simplifySSA again, after which analyzeValues supplies the constants used to resolve indirect call targets (src/service/analysis/native-context.ts). So “the” SSA pass is really a reusable, budgeted transformation, not a one-shot stage.

Everything downstream sees the simplified graph. Call analysis observes argument locations, type recovery reads StackSnapshots and SSA values, and source reconstruction reads the surviving expressions. What this stage explicitly does not do is memory SSA, type inference, alias analysis or structuring; memory stays as ordered load/store nodes and the stack interpreter derives its own conservative memory model.

Registers become cells

A machine register root is not one variable. AArch64 code may read w0, write w0 (which zeroes the upper 32 bits of x0), write a byte of it, and treat xzr as a sink. x86-64 has the same problem with eax/rax and with flags. constructSSA therefore partitions each root into disjoint “cells” at every access boundary and at ABI-observability boundaries, then versions the cells independently. The cell key is the triple used everywhere in the implementation: 

type Cell = RegisterDescriptor;
const key = (cell: Cell): string => `${cell.root}:${cell.offset_bits}:${cell.width_bits}`;

src/analysis/ssa/index.ts (key, build).

The cut set for a root starts as {0, root_width_bits}. Then build adds the low and high edge of every descriptor the body actually reads or writes, a cut every 2048 bits for wide architectural roots, and — for roots the body never touches directly but the ABI can observe — the run boundaries of the ABI mask (see the next section). Adjacent cuts become frozen cells: 

const cell: Cell = Object.freeze({
  ...descriptor,
  id: `ssa:${fingerprint([root, offset, width]).slice(0, 32)}`,
  offset_bits: offset,
  width_bits: width,
  write_rule: 'preserve_other_bits',
});

Two subtleties matter. First, the descriptor collected first is used as the cell template, but an explicit special role wins over general, so sp or zero is not lost when the first view of the root was a generic slice. Second, a root whose actual accesses exist keeps all its segments even when a segment is not ABI-observable; masks prune cells only for roots that never appear in the body (the condition !actualRoots.has(root) when filtering cells). The reason is stated in the code: a later access can require an earlier clobber's slice boundary, so clobber metadata is scanned before it is filtered, and the clobber is still visited and retained even if the mask is empty.

Writes are lowered through the descriptor's write_rule. A preserve_other_bits write rebinds exactly the cells whose ranges lie fully inside the written range; the other cells of the root keep their values. A zero_extend_root write (typical for AArch64 w register writes) also rebinds every other cell of the root to the constant zero. A discard write — xzr — is not a definition at all: the node still contributes provenance, but no cell changes. Reads are the inverse: a read covering one cell resolves directly to that cell's current value, while a read covering several cells is a concat of them, and a read of the zero role is the constant zero.

Invariant

Cells of one root never overlap. For a root the body actually accesses they cover the whole root; for a root known only from clobbers they cover the observable mask runs. Every lowered read_register becomes an assign whose expression is a bitcast of the current cell value (or a concat of them, or the constant zero for the zero role); every write_register disappears as an instruction and only changes the rename state. verifyIR is run by the service after each pass, and the analysis tests assert that no read_register/write_register survives (test/analysis/ssa/ssa.test.ts).

Observable ABI masks

abiObservableRegisterMasks(abi, context) returns a map from register root to a bigint mask of bits that a native ABI boundary can observe. Its header comment is precise about what it is not: 

/** Storage slices that may be observable at a native ABI boundary, not a
 * signature, actual argument list, or proof that any result is written. Source
 * SSA separately keeps every root actually read/written by the lifted body. */

src/analysis/ssa/observable-masks.ts (abiObservableRegisterMasks).

The function marks the stack pointer, every register in abi.preserved, and then probes the ABI's classifyCall with a synthetic catalogue of types: pointers, integers of 1/8/16/32/64/128 bits signed and unsigned, floats of 16/32/64/80/128 bits, vectors of integer and float elements with 64 and 128 total bits, two-word and three-word aggregates, and homogeneous aggregates of one to four elements. For each signature it notes every return location, the hidden-result pointer, every parameter location and every implicit register input. For parameter banks it repeatedly multiplies the parameter list until the last argument spills to the stack or becomes unsupported, which discovers bank capacity without guessing an architectural register count. Two final probes use parameters: null (variadic) and prototyped: false to classify machine-boundary inputs that no source signature can describe.

The masks are properties of the ABI, not of the function. In the Darwin ARM64 profile every observable slice happens to be full width, so observableCuts adds nothing there; the 32/32 split of x0 in Figure 2 comes from the function's own w0 access. The Windows x64 profile is more interesting, and these values are real output for WindowsX64Abi:

Root Mask Consequence
x86_64:rsp, rax, rcx, … 0xffffffffffffffff whole 64-bit root observable
x86_64:zmm1, zmm2, zmm3 0xffffffffffffffff cut at 64; the upper 448 bits are not boundary-observable
x86_64:mxcsr 0xffc0 cuts at 6 and 16; only bits 6–15 can be observed
x86_64:fpcsr 0xffff cut at 16

This is why the masks matter. Without them, every clobbered register of every call would create a cell and a clobber output — a vector bank alone is sixteen zmm roots at 512 bits each — and the SSA graph would be dominated by state nobody can observe. With them, untouched roots are omitted entirely, and touched roots keep their full machine view. Callers that already have masks (for example native dependency preparation) pass them through SSAConstructionOptions.observable_register_masks; a comment there repeats that the masks are a source-view ABI capability, not a prototype.

Refusal

If abi.preserved is not an array, mask discovery throws OperationError with code unavailable_semantics, severity error and message “ABI preservation contract is unavailable for source SSA register masks”. Mask discovery never fabricates a preservation contract.

SSA construction

constructSSA is a thin wrapper: it creates an AnalysisBudget, calls build, and converts any escaping resource_limit or cancelled error into a partial result whose value is the original register IR. RegisterSSAConstruction.construct is the strict variant used through the SSAConstruction interface; it calls build directly and lets errors propagate. The algorithm has six phases.

  1. Collect roots, cuts and cells. Scan every block twice when masks are present: first for the roots actually read or written, then for clobber descriptors and cell construction. Descriptors with role zero are skipped. The cut set and cell creation were described above; the result is a flat cells array plus cellsByRoot for slice matching.
  2. Record per-cell definitions. For every block, a write_register with a non-discard rule defines the cells it fully covers (or all cells of the root for zero_extend_root). A call/unknown_effect defines every cell contained in each descriptor of clobbers.registers and clobbers.flags. This is a Set<number> of block slots per cell, not a per-block state.
  3. Compute dominance and the frontier. computeDominance builds a virtual root over the entry and every unreachable component root, computes immediate dominators iteratively with post-order numbers, and exposes constant-time dominance through dominator-tree intervals (src/ir/dominance.ts). build then computes, for each join with at least two predecessors and a real idom, the standard dominance-frontier walk: from each predecessor, walk idoms up to the join's idom, appending the join to each runner.
  4. Place block parameters. There are no phi instructions. A block's parameters are its phi slots. Every dominator root (entry plus every unreachable component root) starts with every cell as a parameter, because it has no dominating definition. For each cell, the definition blocks plus all root blocks are a worklist; each frontier join not yet placed receives the cell as a parameter and is itself pushed, which is the iterated dominance-frontier placement. Because a merge is an edge argument vector rather than a phi instruction, an irreducible cycle needs no special case: each block simply receives parameters for the cells that meet there (the tests cover a two-entry cycle).
  5. Rename along the dominator tree. A Map<string, Value> holds the current value per cell. Cells merged at a block get fresh values identity(block.id, 'entry', key(cell)); synthesized assignments get identity(block.id, 'generated', sequence++) for the instruction and identity(id, 'value') for its result. Every identity hashes the function, block and birth sequence, so construction is deterministic and a value is never reused across blocks. The traversal is an explicit DFS stack over dominator-tree children with an undo log: every block records marker = undo.length, and on pop restores all entries above the marker. This gives the usual scoped rename without recursion and without cloning the map.
  6. Lower the body and wire the edges. Reads, writes, calls and memory effects are rewritten as described below. At the terminator, each successor edge gets the target block's parameter cells appended in cell-slot order, using the values in scope at the end of the block. All predecessor edges pass their merged cells simultaneously: the argument vector is a snapshot, so a backedge carries the previous iteration's values.

Implemented in src/analysis/ssa/index.ts (build); dominance in src/ir/dominance.ts (computeDominance).

Lowering details are where most of the invariants live. A read of a multi-cell descriptor becomes concat of the cells in ascending offset order; a single-cell read is used directly. In both cases the read node is preserved as assign { id: node.id, result: node.result, expression: bitcast(value) }, so source provenance and the read's identity survive. A write first converts a non-integer value through bitcast, then for each cell inside the range uses the value directly at full width or an extract at cell.offset_bits - descriptor.offset_bits, and stores it through a bitcast assign. Calls and unknown effects snapshot all cells into register_inputs, give every clobbered cell a fresh value identity(node.id, 'clobber', key(cell)), publish them as register_outputs, and thread the effect token from effect_in to effect_out. Loads and stores attach the current register snapshot to their existing effect fields; a fence threads only the effect. The terminator merges its own provenance with the block's provenance and with the provenance of all removed register writes, so a deleted write still explains the value that replaced it.

The shape of the SSA form

The output keeps the original blocks, instructions and terminators but replaces register accesses with assignments and adds parameter vectors to blocks and argument vectors to edges. State is recorded sparsely: 

export interface SSAForm extends FunctionBody {
  readonly form: 'ssa';
  /** One row per block. Entry rows bind every tracked cell to distinct parameters at
   * dominator-tree roots, elsewhere only merged/rebound cells; exit rows bind every
   * cell at function exits, elsewhere only cells rebound in the block. Unlisted cells
   * inherit the immediate dominator's exit (registerStateAt). Rows are observable roots. */
  readonly register_states: readonly {
    readonly block: EntityId;
    readonly entry: readonly RegisterBinding[];
    readonly exit: readonly RegisterBinding[];
  }[];
}

src/ir/model.ts (SSAForm, RegisterBinding, Edge).

The sparsity is important for both cost and correctness. A block's entry row lists the cell parameters created for it; its exit row lists only the cells whose end-of-block value differs from the entry value, except at a function exit, where every cell is listed because the caller can observe the machine state. A consumer that needs the value of any cell at any block calls registerStateAt, which walks the block's entry row, then the exit rows along the dominator chain, and returns null if that chain never binds the exact cell (src/ir/dominance.ts, registerStateAt). This is also why the simplifier treats entry and exit rows as liveness roots: dropping a value just because no expression uses it would erase observable architectural state.

The other structural change is that values live in blocks their definition dominates, not necessarily where they are used. This is standard SSA but has consequences in the implementation: the value analyzer subscribes distant users to definitions, the stack interpreter keeps a remoteUsers map, and the simplifier “pins” a block parameter that is used anywhere other than its own block's terminator before attempting edge threading. Without the pin, an empty pass-through block could be bypassed even though another block's value depended on it.

Invariant: edge arity

For every edge, edge.arguments.length equals the target block's parameters.length, and argument i binds parameter i. build enforces this when it appends the target parameter cells; the tests assert it for every edge of constructed and simplified graphs (test/analysis/ssa/ssa.test.ts). The simplifier's eliminateTrivialParameters removes a parameter and the matching argument from every edge in lockstep.

Budgets and partial results

Three independent limits apply. AnalysisBudget counts abstract work with a default of 1_000_000 units (options.max_work); every loop over blocks, instructions, edges and cells charges it, and it also forwards the count to the operation's checkpoint for cancellation and deadline handling. IRConstructionBudget counts materialized nodes and blocks against max_ir_nodes and max_blocks, reserving three nodes per block (block, effect parameter, terminator) before anything is allocated (src/ir/budget.ts). The service adds a third, post-hoc bound: boundIR recounts the graph and calls assertValidIR after each pass. 

charge(work = 1): void {
  this.work += work;
  if (this.work > this.limit)
    throw new OperationError({ code: 'resource_limit', severity: 'warning',
      message: 'SSA/value analysis work limit reached', … });
}
result<T>(value: T, error?: unknown): AnalysisResult<T> {
  if (error !== undefined && (!(error instanceof OperationError) ||
      (error.code !== 'resource_limit' && error.code !== 'cancelled'))) throw error;
  return { state: error === undefined ? 'complete' : 'partial', value, … };
}

src/analysis/ssa/budget.ts (AnalysisBudget, AnalysisResult).

The transactional rule is that a pass boundary never publishes a half-rewritten graph. constructSSA returns the original RegisterIR when it runs out of budget, so the caller sees state: 'partial' and a non-SSA value. simplifySSA returns the last complete graph — the one before the failing round. analyzeValues returns an empty fact map, because facts that did not converge are not proofs. recoverStack returns the empty result with zeroed frame bounds and no snapshots.

The service does not silently accept any of these. requirePass rethrows resource_limit and cancelled, and maps every other partial state to unavailable_semantics (“Analysis pass did not produce a complete valid representation”). Only the native-preparation path deliberately converts a local work-limit failure into a partial dependency with a reason string.

Limit interaction

The limits are not interchangeable. A graph can be under the work counter and still exceed max_ir_nodes, and a graph under both can still fail boundIR's assertValidIR. The diagnostics differ: resource_limit with details.resource: 'work', 'ir_nodes' or 'blocks'.

Value analysis

analyzeValues is a conditional propagation over the SSA graph. Its lattice has only three points: “no fact” (bottom), an exact bit pattern, and varying (top). There are no ranges, no known-bit masks and no congruences; a value is either a constant or it is not. 

export type ValueFact =
  { readonly kind: 'constant'; readonly bits: bigint } | { readonly kind: 'varying' };
export interface ValueAnalysis {
  /** Missing facts are bottom. Partial results clear facts: unconverged constants are not proofs. */
  readonly facts: ReadonlyMap<EntityId, ValueFact>;
  readonly reachable_blocks: ReadonlySet<EntityId>;
  readonly executable_edges: ReadonlySet<Edge>;
}

src/analysis/values/index.ts (ValueFact, analyzeValues, propagate).

The pass first builds four indexes: home (defining block of every result), operands (the values read by each assignment), users (blocks using a value, including branch and switch conditions) and phiUsers (for an edge argument, the target parameter slot it feeds). The worklist holds blocks, not values. The entry block is reachable, its parameters are forced to varying, and propagation proceeds as follows:

  1. Fold assignments in order. A non-assign instruction makes its results varying. For an assignment, a select with a constant condition takes the chosen arm's fact directly. If any operand is already varying, or the expression is indeterminate, the result is varying. If any operand has no fact yet, the assignment is skipped for now. Only when all operands are constants is evaluateExpression called, with the trusted bit-vector/FP semantics.
  2. Select executable edges. A branch with a constant condition marks only one edge executable; a varying condition marks both. A missing condition marks none. A switch uses the matching case or otherwise for a constant selector, all edges for a varying one. Every other terminator marks all successors executable.
  3. Subscribe and contribute on each edge. The first time an edge becomes executable, every argument is subscribed to its target parameter slot and contributes its current fact. Later changes to an argument notify only the subscribed slots. If a parameter's fact changes or the target became newly reachable, the target block is enqueued.
  4. Flush notifications carefully. When a value changes, all using blocks are enqueued except the currently active block's own same-block uses; those follow the definition in instruction order. Phi contributions are applied immediately. This rule is what keeps the walk ordered within a block while still allowing a dominating definition changed by a loop delivery to reschedule its users.

change is monotone: the first fact is stored; any later different fact replaces it with varying; once varying, nothing changes. That is the whole join rule, and it is why the code can promise a “monotone finite-height lattice, including loop backedges”. A loop's first-iteration constant is therefore not published as the loop value: the backedge delivers a different fact and the parameter becomes varying.

The analysis also records reachable_blocks and executable_edges; simplifySSA consumes both to delete unreachable blocks and to thread branch edges only along edges proven executable. Because the fact map is keyed by value identity, the same analysis result is used for folding, branch pruning, switch selection and the simplifier's edge-specific predicate reasoning.

Simplification rules

simplifySSA runs a fixed-point loop. Each round propagates facts, rewrites expressions and terminators, propagates same-type bitcasts, and eliminates trivial block parameters. The loop repeats while any of the three reports a change: 

let changed = true, first = true;
while (changed) {
  const analysis = { facts: new Map(), reachable_blocks: new Set(), executable_edges: new Set() };
  propagate(current, budget, analysis);
  const rewritten = rewrite(current, analysis, budget);
  const copies = propagateCopies(rewritten.value, budget);
  const trivial = first || rewritten.changed || copies.changed
    ? eliminateTrivialParameters(copies.value, budget)
    : { value: copies.value, changed: false };
  first = false;
  changed = rewritten.changed || copies.changed || trivial.changed;
  current = trivial.value;
}

src/analysis/values/index.ts (simplifySSA, rewrite, propagateCopies, eliminateTrivialParameters).

rewrite rewrites in place functionally: it builds new instruction and block arrays and preserves identities. For every assignment it first calls recoverComparison (next section), then applies one of the rules below. If the expression object changed, it merges the provenance of the old expression's defining assignments into the replacement's provenance and updates the definition map so later rules see the new form.

Rule Condition Replacement
Constant fold the fact of the result is a constant, and the expression is neither constant nor address constant(fact.bits)
Select fold select whose condition fact is a constant bitcast(chosen arm)
Right identity right operand is 0 and the op is add, sub, or, xor, shl, lshr, ashr, rol or ror bitcast(left)
Times one right operand is 1 and the op is mul or udiv, or sdiv with result width > 1 bitcast(left)
Mask all ones op is and and the right operand is 2^width - 1 bitcast(left)
Branch prune branch condition fact is constant jump to the taken edge; the other edge disappears with its block if unreachable
Switch prune switch selector fact is constant jump to the matching case or otherwise
Dead assignment result not in the liveness set removed; provenance merged into the block
Copy propagation cast bitcast whose operand has the same type every reference aliases the source; the copy node is removed
Trivial parameter a non-root block parameter whose incoming edge values are all one value v (at least one) or the parameter itself parameter and its edge slot removed; references become v
Edge threading target is an empty non-entry block, not pinned, with no register-state rows edge retargeted through it with substituted arguments

Two deliberate non-rules are documented in the code: x - x and x * 0 are not folded, because those identities would erase an undefined or unknown operand. (Multiplying by one is safe.) Likewise the constant-fold rule refuses to replace an address expression with a plain constant: the symbolic address carries image and space information that later stages need.

Liveness is global and computed after rewriting. The roots are: the operands of every non-assign instruction (including the register snapshots on loads, stores, calls and unknown effects), all terminator operands including edge arguments, and every value in every register-state entry and exit row. From those roots the pass walks defining assignments backwards and marks their expression operands. Only then does it sweep each block backwards, deleting unmarked assignments and merging their provenance into the block. This ordering is what keeps observable state alive: a value that is only referenced by a register snapshot or an exit row survives even when no ordinary expression reads it.

Copy propagation is restricted to same-type bitcasts, i.e. genuine copies. It resolves whole copy chains, then removes every copy node and substitutes the final source at every reference, including register-state rows and edge arguments. Provenance is merged into same-block consumers; when the source lives in another block, the copy's origin joins its own block's provenance instead, and dominated consumers simply reference the value. Eliminating trivial parameters is proved safe by the comment on the function: the first entry along every path must carry v from a non-dominated predecessor, so v's definition dominates the block; the parameter and its edge slots can disappear, while architectural entry bindings are remapped to v.

Edge threading is deliberately narrow. It may bypass only a block with zero instructions, no entry or exit state rows, which is not the function entry and is not pinned because one of its parameters is used elsewhere. A jump is followed unconditionally; a branch is followed only if its condition is a constant or is exactly the condition the incoming edge already proved (the edge-specific { value, truth } pair). A cycle that would merely rotate parameters is refused by returning the original edge. The tests include a dedicated case for effect-free cycles that must not rotate forever (test/analysis/values/values.test.ts).

Flags to comparisons

Lifters model condition flags as first-class expressions, not as source syntax. A subtraction produces flag expressions such as flag.sub.zero, flag.sub.carry, flag.sub.borrow, flag.sub.negative and flag.sub.overflow, each carrying the two operands and the incoming carry. A conditional select or conditional branch then combines them. recoverComparison turns those combinations back into integer comparisons when the shape proves a two-operand relation; it never reads architecture spellings, so the same rules serve ARM64 NZCV and x86 flags. 

export function recoverComparison(
  expression: Expression,
  definitions: ReadonlyMap<EntityId, Assignment>,
  facts: ReadonlyMap<EntityId, ValueFact>,
): Expression

Two helpers do most of the structural work. resolve follows definition chains through same-width bitcasts (with a cycle guard) and returns the underlying expression. zeroCarry accepts a carry operand only when its fact is the constant zero or its definition is the constant zero. That is why a subtraction with a nonzero borrow-in is never rewritten as a two-operand comparison; the test suite has a specific case asserting the flag survives.

Pattern (1-bit unless noted) Condition Result
flag.sub.zero(l, r, c) zeroCarry(c) eq(l, r)
flag.sub.carry(l, r, c) zeroCarry(c) uge(l, r)
flag.sub.borrow(l, r, c) zeroCarry(c) ult(l, r)
xor(flag.sub.negative(l,r,c), flag.sub.overflow(l,r,c)) same l, r and carry identities; zeroCarry(c) slt(l, r)
xor(cmp, 1) either operand is a compare, the other the constant 1 complement predicate (eq↔ne, ult↔uge, …)
not(cmp) operand resolves to a compare complement predicate
or(cmpA, cmpB) / and(cmpA, cmpB) identical operand identities and compatible signedness predicate whose 3-bit relation mask is the OR/AND of both masks
eq/ne(cmp, 0/1) one side is a compare, the other a constant the compare or its complement

The relation-mask encoding is small and worth knowing: eq = 2, ne = 5, ult = 1, ule = 3, ugt = 4, uge = 6, with the same masks for the signed predicates. eq and ne have signedness null; combining them with a signed or unsigned predicate is allowed, and combining a signed with an unsigned predicate is not.

Recovery is structural, not symbolic

recoverComparison sees only the expression object and the definition map; it does not know the source operator or the machine instruction. That makes it architecture-neutral, but it also means any shape the lifter does not produce verbatim stays unrecovered. The test “compound flag predicates recover signed and unsigned inclusive/strict conditions” shows the supported shapes (sle, sgt, ugt) when flags appear directly as operands.

Stack recovery

recoverStack(input, abi, context, options) is a separate, non-rewriting abstract interpreter over the SSA graph. It is shared, read-only and does not mutate the input. Its purpose is to answer questions the SSA cannot: what is the value of a stack slot at a given instruction, which stack bytes were initialized on all paths, does a stack pointer escape, and how do callee-entry offsets map to locals versus incoming arguments. 

export type StackValue =
  | { readonly kind: 'constant'; readonly bits: bigint }
  | { readonly kind: 'address'; readonly address: Address }
  | { readonly kind: 'stack'; readonly offset: bigint }
  | { readonly kind: 'stack_fragment'; readonly offset: bigint;
      readonly offset_bits: number; readonly width_bits: number }
  | { readonly kind: 'dynamic_stack' | 'unknown' | 'undefined' };

src/analysis/stack/index.ts (StackValue, StackFact, StackByte, StackSnapshot, recoverStack, inspectStackMemory, inspectRegister).

A StackFact pairs a StackValue with an initialization state (initialized, uninitialized, maybe_initialized, unknown), the contributing value IDs, evidence IDs and the physical entry registers it depends on. The byte-level memory is a Map<bigint, StackByte> keyed by callee-entry stack-pointer offset; each StackByte stores the fact of the write that produced it plus value_offset_bits, which selects which byte of a wider stored value this is. A snapshot is the register facts plus the memory map plus the current stack-pointer fact and the escape/alias flags.

Entry state is built from the entry block's register parameters. The stack-pointer parameter becomes stack { offset: 0n } when the cell is the full 64-bit pointer, or a stack_fragment when only a slice is bound. Every other entry parameter is unknown. There is no attempt to interpret caller memory: entry memory is empty and absent bytes behave differently above and below entry SP.

Stack taint is sticky by design. noteStackBindings records every value bound to a stack-pointer cell, both in the register-state rows and in instruction snapshots, and get promotes any such value whose fact is no longer stack-derived to dynamic_stack. That covers a join of two different offsets, a partial overwrite of the pointer slice, and a replacement by an unknown value. This is why the result can say “this is still stack-derived, but no longer a fixed offset” instead of silently returning unknown.

The solver is a reverse-postorder priority worklist. A DFS over all components (entry first) assigns post-order ranks; a binary heap keyed by rank schedules blocks, using arrays reused from the DFS so that enqueueing allocates nothing. Every pending block has one fixed slot, including backedges and disconnected components. Transfer of a block publishes its parameters, then walks instructions:

  • assign evaluates the expression in the stack domain. add/sub of a stack value and a constant adjust the entry-relative offset with 64-bit wrapping; bitcast and zero-offset same-width extract forward their operand; an extract of a stack value produces a stack_fragment with the added bit offset; concat reassembles a full pointer only when every original bit survives at the right offset; anything else falls back to evaluateExpression, then to dynamic_stack if an operand is stack-derived, otherwise unknown.
  • load/store snapshot the pre-effect register state, compute the address fact, and use the entry-relative offset if the address is a full stack value. A load reads bytes through inspectStackMemory and publishes the result. A store writes one StackByte per byte, with the stored fact and the byte's bit offset; a width that is not a multiple of 8 degrades to unknown or dynamic_stack with initialization unknown rather than padding bits. A non-stack address marks escape if the stored value is stack-derived and then applies a whole-stack barrier.
  • call/unknown_effect snapshot the pre-call state. If any argument, any non-SP register input, or any tracked stack byte holds a stack value, the state is marked escaped. An unknown_read_write memory clobber applies the barrier. Register outputs and call results are published as unknown.
  • A return terminator marks escape if a returned value or any exit register that the ABI does not preserve holds a stack value.

Transfer, worklist and join live in src/analysis/stack/index.ts (transfer, stackWorklist, join).

A barrier is deliberately blunt: it sets aliased and rewrites every tracked byte to unknown/dynamic_stack with initialization unknown unless it is already fully unknown. It is idempotent, guarded by a WeakSet of byte maps. The code calls this “deliberately conservative, not a points-to analysis”. Working states share memory maps with predecessors and snapshots until their first write, at which point the map is copied; byte records themselves are immutable.

Joins are byte-precise. Parameter facts join pairwise. Memory joins every offset present in either state; a missing byte is uninitialized below entry SP when the state is not aliased, and unknown above it. If two states disagree about the byte's value_offset_bits, the merged byte's value degrades to unknown/dynamic_stack. The join of two different non-stack values is unknown; if either side is stack-derived it is dynamic_stack. Initialization joins as: all initialized → initialized; all uninitialized → uninitialized; any unknown → unknown; otherwise maybe_initialized.

After the fixpoint, a recording pass reruns every reachable block. It stores a StackSnapshot before each load, store, call and unknown effect, and an exit snapshot under the terminator's ID; it records a StackAccess for every load/store whose address is stack-derived; and it widens frame.minimum_offset/maximum_offset from stack facts and access ranges. frame.dynamic becomes true when the stack pointer stops being a known stack value or an access has no known offset; escaped and aliased are latched from the states. The result also exposes values (the final fact of every published SSA value, used by call analysis for argument observation) and entry, the synthesized entry snapshot with an empty memory map and the initial register facts.

Refusal and exhaustion

max_stack_bytes defaults to 65_536 and must be a nonnegative safe integer no larger than that; otherwise recoverStack throws RangeError('Invalid stack byte bound'). Exceeding the bound, or the work budget, throws the analysis resource error, and recoverStack returns the empty result with state: 'partial', empty snapshots and zeroed frame bounds. inspectStackMemory independently rejects sizes above 65,536 bytes with RangeError.

Byte model and region classification

inspectStackMemory(snapshot, offset, size, endian = 'little') is the read side of the byte model. It gathers one byte record per address, substituting the absent-byte rule for gaps, and then:

  • if any byte is undefined, the whole observation is undefined and initialized as uninitialized;
  • if all bytes carry the same fact with the expected per-byte value offsets, and the size is 8, and the value is a stack or address, it returns that fact unchanged — this is pointer identity, not a numeric assembly;
  • if every byte is constant, it assembles the bits in the requested endianness;
  • otherwise the result is dynamic_stack if any byte is stack-derived, else unknown.

inspectRegister is the register-side analogue. It finds all snapshot bindings of the same root that overlap the requested range, sorts them by offset, and requires them to cover the range contiguously; a gap yields unknown. A single binding covering exactly the request is returned as-is. Otherwise constants are assembled with masking, and a full 64-bit request at offset 0 may be reassembled into a stack value via assembleStack, which requires every original pointer bit and a consistent offset.

Region classification uses callee-entry SP coordinates, never the current allocated frame: 

export function classifyStackRegion(abi: AbiProfile, offset: bigint | null, size: bigint) {
  if (offset === null) return 'dynamic';
  const classify = (at: bigint) => at < 0n ? 'local_candidate'
    : at < abi.stack_return_address_bytes ? 'return_address'
    : abi.id === 'windows-x64' && at < 40n ? 'shadow_space'
    : 'incoming_candidate';
  return classify(offset) === classify(offset + size - 1n) ? classify(offset) : 'mixed';
}

Effect summaries

Register state is versioned, but memory, calls and fences are ordered by a single effect token. A block has an effect_parameter; every memory or call node carries effect_in and effect_out; every edge carries the block's final effect. Register effects disappear in SSA (there is no token for a register write), while the relative order of memory reads, writes, calls and fences is preserved exactly. This is the contract the stack interpreter and later emitters rely on: they may drop a dead pure assignment, but they may never reorder or drop an effectful node.

Ordering invariant

constructSSA preserves memory/call/unknown effect order and drops register effects; simplifySSA preserves all effectful nodes; recoverStack interprets them in block order with snapshots taken before each effect. No pass reorders effects to make an optimization fire.

Why _fixture_loop looks different

The loop function's simplified form still contains eight parameters on its header and explicit concats for the packed NZCV register. Loop-carried cells cannot become trivial — at least two incoming values differ — and flag packing is ordinary integer data flow, so it is not removed. The graph is still constant-folded and bitcast-free; it is simply not a straight-line function. Page Source reconstruction consumes exactly this shape.

Limitations & extension points

The stage is intentionally narrow. The value analysis knows only “constant” or “varying”; there is no range, known-bits, congruence or pointer-offset domain. Memory is not in SSA: loads are never forwarded from preceding stores, calls are never summarized as memory values, and the only byte-precise memory model is the separate stack interpreter. Stack aliasing is a whole-stack barrier rather than points-to: one unknown store or unknown memory clobber discards all tracked precision, and a stack pointer that escapes is tracked but not followed. Frame bounds are candidate offsets, not a proven frame size, and negative offsets never prove a local's source type.

Parameter placement uses the iterated dominance frontier and simultaneously transferred edge arguments, which handles loops and irreducible components without phi instructions, but it is not a minimal SSA construction: the roots bind every cell, and the simplifier, not the constructor, removes trivial parameters and unreachable blocks. If simplification is interrupted before its first complete round, those blocks and parameters remain in the returned last-complete graph. On a work-limit failure constructSSA returns the original register IR, so callers must check state before touching form.

Observable masks depend on a complete ABI preservation contract and on repeated classifyCall probes. They describe which storage an ABI boundary can observe, not a signature: a mask does not claim that a register holds an argument, only that it could be observed. A backend that cannot supply abi.preserved is refused rather than approximated. Conversely, a root the body actually touches is always materialized, even when its mask is zero, so the machine view of the function itself is never lost.

recoverComparison is a structural matcher. It follows same-width bitcasts but not extracts or inserts, requires a zero incoming carry for the subtraction rules, and only combines two comparisons whose operand identities are identical. Real ARM64 code that packs flags into NZCV and then extracts them can therefore leave a signed composite such as and(eq(N, V), not(Z)) intact, as Figure 5 shows; the semantics are still correct, but downstream code sees the flag composition rather than sgt. The tests document the shapes that are recovered.

Adding a simplification rule

  1. Choose the rewrite point. Expression-level rules go in rewrite in src/analysis/values/index.ts, after recoverComparison and before the constant-fact rule if you want the fact to win, or after it if the rule needs the original expression. Terminator rules go in the branch/switch section of the same function.
  2. State the precondition in terms of facts and identities. Rules may inspect analysis.facts, the definition map (for recoverComparison-style look-through) and the expression shape. A rule that needs “known value” must use a fact, not an assumption about the lifter, and it must not fold an indeterminate operand.
  3. Return a new expression and merge provenance. rewrite already merges the provenance of the old expression's defining assignments when the expression object changes; keep that path by returning a new object rather than mutating. Preserve the instruction ID and result value; downstream stages key facts and source maps by identity.
  4. Prove it with the equivalence harness. The tests in test/analysis/ssa/support.ts run the program, the SSA form and the simplified form through evaluateIR and compare returned values, memory, effect trace and known/undefined register masks. That is the right oracle for a new rule: a rule that changes observable registers or effect order will fail even if the returned value matches.
  5. Respect the fixed point. A rule must be monotone in the sense that it either shrinks the expression or is idempotent; otherwise simplifySSA's while (changed) loop will not terminate, and the edge-threading cycle guard exists precisely because a naive rewrite can rotate forever. Add a test with a small max_work to confirm the partial result is still valid.

Adding a stack region means extending classifyStackRegion with an ABI property and updating the region table and tests; adding register observability means extending abiObservableRegisterMasks's probe catalogue, not special-casing a register name in construction. Adding a new fact kind to value analysis is a larger change: the lattice join in change and the operand handling in propagate must both be extended, and every consumer that assumes constant or varying must be audited.
