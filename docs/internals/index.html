Overview

Architecture overview

Open Decomp is a static native-binary decompiler: binary formats become an immutable image, the image becomes a CFG, the CFG becomes typed SSA, and the SSA becomes C-like or Python-like pseudocode with evidence attached to every derived fact. This page maps the module graph, the process boundaries, the per-target component set, the cache identity and the seven progress stages of one decompile request.

Where this sits in the pipeline

The decompiler is a single TypeScript code base (96,896 lines under src/) with three targets: Mach-O on AArch64 with the Darwin ABI, PE on x86-64 with the Microsoft x64 ABI, and ELF on x86-64 with the System V AMD64 ABI. Those triples are the only values targetSchema accepts; it also pins little-endian, 64-bit addressing and a feature string list. src/core/primitives.ts (targetSchema).

Technically the system is four things stacked on one contract vocabulary:

  1. A binary reader. A format loader produces a LoadedImage: immutable bytes, selected slice, mappings, sections, symbols, imports, exports, relocations, loader hints, evidence and diagnostics. src/core/model.ts (LoadedImage).
  2. A machine-semantics pipeline. Decoding produces DecodedInstruction records; discovery builds CFGBlocks; a lifter produces the typed RegisterIR; SSA construction, value simplification, call/ABI recovery and type recovery operate on that IR. src/core/contracts.ts (Decoder, Lifter, AbiProfile).
  3. A source projection. Structuring turns the CFG into nested regions; reconstruction maps SSA values, stack slots and calls onto a C-like source model with explicit uncertainties; an emitter renders that model. src/presentation/index.ts (structureControlFlow).
  4. A durable project. A SQLite store keyed by content hash holds the imported image, native facts, annotations, jobs and published analysis artifacts, all at explicit revisions. src/project/store/index.ts (SqliteProjectStore).

The design principles that a reader will see enforced over and over are:

  • The target never executes. The README states analysis happens “without source code or executing the target”, and the MCP surface advertises “No target execution, dynamic plugins or URL fetching” (src/mcp/server.ts, trustBoundary). Image bytes live in ImmutableBytes, which copies on construction and exposes no mutable view (src/core/addresses.ts).
  • Refuse or mark partial rather than guess. Component dispatch throws unsupported_target; an ambiguous function name is an error, not a first match; a pass that cannot produce a complete representation throws unavailable_semantics; unresolved call interfaces stay as ... and carry a diagnostic.
  • Evidence-bearing output. Diagnostics and presentation records cite evidence_… identities; analysis closes the proof graph before publishing, and an unavailable proof is an internal_error, never a silently omitted citation (closeEvidence in src/service/analysis/catalog.ts).
  • Determinism and content identity. Identity is computed from canonical, type-tagged data with sorted keys; the project directory is the SHA-256 of the input plus the selected slice; the analysis cache key is a fingerprint of a CacheIdentity. src/core/identity.ts (canonicalIdentity, fingerprint).
  • Budgets everywhere. Every operation carries a Budget and an OperationContext.checkpoint that charges actual work; instruction, block, IR-node, work, deadline and output limits are enforced at different layers, and the budget is part of the cache identity.
What “complete” means

A complete result means the requested bounded operation finished with every coverage layer complete — not that every architecture feature or every callee is understood. Per-layer coverage remains authoritative, and docs/CORE.md says the same explicitly.

Layers, processes and the tool surface

Everything below the transport is expressed with 14 tool operations (project_open, project_close, binary_info, symbols_find, strings_find, functions_find, function_get, function_decompile, xrefs_get, evidence_get, memory_read, annotations_apply, analysis_status, analysis_cancel) declared once in toolSchemas. src/core/tools.ts (ToolSchemaRegistry, toolSchemas).

Surface Entry point Transport behaviour
CLI open-decomp functions|decompile|export|types → src/cli/entry.ts (runAnalysisCli) Pseudocode on stdout, progress/diagnostics on stderr; exit 0 complete/empty, 2 semantic partial, 1 error/unsupported/cancelled.
MCP stdio src/mcp/server.ts + src/mcp/cli.ts JSON-RPC; stdout is reserved for protocol traffic; messages bounded to 2 MiB (MCP_MAX_RESULT_BYTES).

All four surfaces converge on QueryService, which parses the input schema before admission and then submits a tool-shaped command to a per-project child process. The child parses the same schema again in dispatch: the host parse stops invalid requests early, and the child parse is the trust boundary for a process that owns the store. src/service/queries/index.ts (QueryService.execute), src/service/queries/handler.ts (dispatch).

The pool keeps one persistent child per canonical project. ProjectWorkerPool bounds max_workers to 2 by default (range 1–32) and max_queued to 16 (range 0–1024); the CLI's BinarySession deliberately creates the service with max_workers: 1. IPC is length-prefixed JSON frames with MAX_FRAME_BYTES = 2 * 1024 * 1024 and at most 256 images per project (MAX_IMAGES). src/workers/index.ts, src/workers/protocol.ts.

Below the pool, durability and derivation are deliberately split. Every durable fact — images, native records, evidence, types, signatures, annotations and jobs — goes through ProjectStore, whose transactions are revision-checked. Derived analysis is not a table of mutable results: runCachedDecompilation looks up a published artifact by exact cache key, tries up to eight reuse candidates and validates a recorded dependency readset, and only then computes; publication is a separate atomic step tied to the job and the expected revision. With analysis_cache: false, the same result is served from a transient in-memory artifact and nothing derived is indexed. src/project/cache/index.ts (runCachedDecompilation). The emitters are the last layer: they consume the structured presentation and produce the wire Emission, which is the only artifact the transports ever render.

What validation actually checks

validateToolRequest parses the operation's Zod schema, then enforces cross-field preconditions that a structural schema cannot express: a supplied revision or expected_revision must equal the current revision (otherwise RevisionConflict, code stale_revision), and an address or range must belong to the named image. src/core/validation.ts. validateToolResponse goes further on the way out: the result must parse against the output schema, belong to the same project and revision, mutations must advance exactly one revision, a queued job must describe the same operation, and the serialized result must fit args.budget.output_bytes.

Invariant

A successful mutation advances the project revision by exactly one (nextRevision), and a transaction either commits whole or rolls back. The store's transaction(expectedRevision, mutate) compares the expected revision before running mutate; a throw rolls back, and a conflicting expectation returns { state: 'conflict' }. src/project/store/index.ts (#transaction, snapshot).

Three properties of this graph matter architecturally:

  • core is generic, not semantic. It declares Lifter<RegisterIR> and Emitter<Presentation> without importing ir or emitters; the comment on Lifter says “the semantic IR module supplies RegisterIR. Core does not define semantic operations”. src/core/contracts.ts.
  • Directory-level cycles exist; file-level ones are cut by composition roots. service imports workers for the pool, while workers/entry.ts imports queryWorkerHandler from service/queries/handler.ts; mcp and settings import each other. These are wiring edges, not stage dependencies.
  • Type-only edges point backwards. reconstruction imports EmissionInput (emitters), NativeContext (service), TypeRecoveryResult (analysis) and presentation types, all with import type. That is what lets reconstruction describe a render target without creating a runtime cycle.

Per-target components and cache identity

Component selection is not a plugin registry. The live registry is the frozen components object in versions.ts, keyed by darwin_arm64, windows_x64 and sysv_amd64. targetPipeline first requires little-endian 64-bit addressing and then matches the complete format + architecture + ABI triple; anything else throws unsupported_target with “No complete lifter/ABI pipeline is registered”. src/service/analysis/versions.ts (pipelineComponents, targetPipeline).

One decompile request, end to end

The example command is open-decomp decompile fixtures/bin/macho-arm64-symbols --function _fixture_maximum. Each numbered step names the function that actually runs.

  1. CLI parse. parse accepts exactly one of --function, --id or --address; the function selector is { name: '_fixture_maximum' }. Settings are resolved as built-in default < settings file < explicit flag. src/cli/commands.ts.
  2. Project open. BinarySession.open canonicalizes the path, hashes the whole file with hashInput (refusing a symlink, a file over 512 MiB, or a file that changes while hashing), derives the project directory as <sha256>.<slice|default>, creates a QueryService with one worker, and sends project_open with { kind: 'import', wait: true }. src/api/index.ts (BinarySession.open), src/service/queries/input-identity.ts (projectDirectoryName).
  3. Image snapshot and discovery. The child re-checks the canonical path, reads the file with O_NOFOLLOW into ImmutableBytes, chooses the loader by magic (MZ → PE, 0x7f ELF → ELF, otherwise Mach-O), calls loader.load, stores the image with importImage, then runs prepareQueryImport: recoverRuntimeMetadata, decorateImageNames, discoverFunctions, buildStringIndex, buildReferenceIndex, classifyImportStubs. Image, indexes and the completed job commit in one transaction. src/workers/runtime.ts (execute, import branch), src/service/queries/prepare.ts.
  4. Function resolution. BinarySession.decompile calls selectFunction, which asks functions_find for an exact, case-sensitive name and refuses more than one match. If the function index is partial, it falls back to the authoritative native symbol and export tables through symbols_find; anything they cannot settle stays incomplete, never guessed. src/service/queries/selector.ts (selectFunction, selectByNativeName).
  5. Job admission. decompileFunction submits function_decompile with wait: true. The host frames admit; the child creates and persists the durable queued job, then creates an OperationContext whose deadline is capped by the admission deadline. src/service/queries/index.ts (submit), src/workers/runtime.ts (createOperationContext).
  6. Analysis. dispatch routes function_decompile to executeDecompilation, which checks project ownership, builds the CacheIdentity and calls runCachedDecompilation. On a miss, the seven stages below run.
  7. Delivery. The stored result is delivered inline if its JSON fits inline_limit; otherwise the envelope becomes state: 'partial', reason: 'output_limit' plus an artifact handle. The CLI prints emission.text after materializeDecompilation has verified the artifact's pages, digest, project, revision, versions, options and budget. src/service/queries/materialize.ts.

The analysis works against a fullContext whose output_bytes is raised to MAX_ANALYSIS_ARTIFACT_BYTES (16 MiB), while the deliverable inline limit is min(args.budget.output_bytes, scope.max_result_bytes, MAX_FRAME_BYTES - 16384). Worked example: _fixture_maximum

The fixture source is a three-instruction conditional select. From fixtures/source/corpus.c: 

API NOINLINE i32 fixture_maximum(i32 a, i32 b) { return a > b ? a : b; }

The function record is entity_835a96c5…f1817f at va:0x100000588. Asking the project for the disassembly returns exactly three valid instructions, each with its own entity ID, byte range and decoder payload:

VA Mnemonic Encoding Flow
0x100000588 SUBS w31, w0, w1 SUBS_32_addsub_shift fallthrough
0x10000058c CSEL w0, w0, w1, gt CSEL_32_condsel fallthrough
0x100000590 RET RET_64R_branch_reg return

The CLI run (stdout only; progress and project reuse go to stderr) produced:

$ node dist/src/cli/entry.js decompile fixtures/bin/macho-arm64-symbols \
    --function _fixture_maximum --cache /tmp/od-cache
/* C-like */
int32_t fixture_maximum(int32_t arg0, int32_t arg1) {
  return arg0 > arg1 ? arg0 : arg1;
}

The unsimplified view of the same function shows what “checked” means — every machine fact stays explicit, including the register-width casts and the unsigned intermediate value: 

$ node dist/src/cli/entry.js decompile fixtures/bin/macho-arm64-symbols \
    --function _fixture_maximum --view checked --cache /tmp/od-cache
/* C-like */
uint64_t fn__fixture_maximum(uint64_t arg0, uint64_t arg1) {
  return ((uint64_t)(((((int32_t)(((uint32_t)(arg0)))) > ((int32_t)(((uint32_t)(arg1))))) ? ((uint32_t)(arg0)) : ((uint32_t)(arg1)))));
}

The structured envelope reports state: "complete", cache: "hit" (this was the second run), five coverage layers all complete (decode 11/11, lift 11/11, abi 1/1, analysis 1/1, reconstruction 40/40), and the emission carries 23 source mappings and two evidence records for a 105-character text. The call’s versions identify exactly the components from Table 3: open-decomp-macho/1.0.4, aa0e547…+adapter.2, ARM64 typed semantic lifter/1.0.6, darwin-arm64/1.3.0, reconstructed-c-53.

Cross-cutting concepts

OperationContext and budgets

export interface OperationContext {
  readonly signal: AbortSignal;
  readonly budget: Budget;
  /** Implementations must charge actual work and throw a typed resource-limit/cancel error. */
  checkpoint(work: number): void;
  /** Actual shared work remaining; methods survive context wrappers/spreads. */
  remainingWork?(): number;
  progress(phase: string, completed: number, total: number | null): void;
}

One context per operation: counters and the monotonic deadline are never reset by a pass. createOperationContext freezes the parsed budget and samples the clock only every 32 charges (clockCountdown = 31), latching expiry so later charges fail identically; this is explicitly to keep the clock read off the hot path of analyses that “charge millions of times per request”. A charge that is not a nonnegative safe integer throws RangeError; an aborted signal throws cancelled; an expired deadline or exhausted work counter throws resource_limit with details.kind: 'limit' and the resource name. src/core/operation.ts.

Budget field Default Enforced where
instructions 10,000 Discovery stops at the cap; lifters reject an oversized graph; a budget gap aborts the decompile.
blocks 10,000 boundIR, discovery, pass options.
ir_nodes 100,000 boundIR (3 + parameters + instructions per block) and the IR builder.
work 10,000,000 Every checkpoint; also passed to passes as max_work.
deadline_ms 30,000 checkpoint, capped again by the worker's admission deadline.
output_bytes 1,048,576 validateToolResponse and delivery; analysis itself runs with a 16 MiB allowance.

OperationError and diagnostic codes

OperationError carries one Diagnostic; its code getter is the diagnostic code. Diagnostics are also used as non-fatal warnings: an unsupported instruction is a warning unavailable_semantics on the instruction, while a pass that cannot produce a complete form escalates it to an error. The envelope keeps up to 1,000 diagnostics; the CLI collapses them with caveats() into reader-facing lines, grouping unresolved call interfaces, return storage and partial callees, and hiding info records. src/core/diagnostic-summary.ts.

Complete, partial and refusal

Result envelopes are a discriminated union over complete, empty, partial, queued, running, unsupported, failed and cancelled. A partial result always carries a reason — budget, incomplete_index, unsupported_subset or output_limit — and a continuation (always null for decompilation). src/core/tools.ts (ResultEnvelope, projectDecompilationArtifactResult). 

export function requirePass(
  state: 'complete' | 'partial',
  diagnostics: readonly Diagnostic[],
  context: OperationContext,
): void {
  context.checkpoint(0);
  const failure = diagnostics.find(
    (item) => item.code === 'cancelled' || item.code === 'resource_limit',
  );
  if (failure) throw new OperationError(failure);
  if (state === 'partial')
    throw new OperationError({
      code: 'unavailable_semantics',
      // …
    });
}

src/service/analysis/passes.ts (requirePass).

Evidence and provenance

Evidence is a revisioned record with an origin that is one of five kinds — binary (range + description), analysis (analyzer, version, rule), debug (artifact id, record, whether identity was verified), library (library, contract, version), or assertion (author, user or LLM, status) — plus claim, derived_from and conflicts_with. The schema rejects self-derivation and self-conflict. src/core/primitives.ts (evidenceSchema).

Navigation results cite evidence IDs; evidence_get resolves them, and derivation: 'closure' walks ancestors. Inside one emission, every proof is interned once in emission.evidence and cited by index, which is why an emission's mappings are compact even when many spans share a proof. The presentation status vocabulary — established, inferred, asserted, hypothesis, conflicting, assumption, unresolved — is separate from semantic coverage; the comment in inference.ts warns that “presentation confidence is not semantic coverage or a translation proof”. src/core/inference.ts.

Revisions, snapshots and cursors

A project is a sequence of revisions starting at 0. snapshot(revision) returns the project id, schema version and every image imported at or before that revision (with its selected slice); reading a future revision is stale_revision. Jobs record input_revision separately from published_revision, because a long-running analysis publishes into the revision it started from and a newer annotation does not retroactively authorize it. Annotations are applied in a batch with expected_revision; the result is committed, conflict or rejected, and a commit advances exactly one revision while invalidating derived analysis before that point. src/project/store/index.ts (applyAnnotations, snapshot).

Paging cursors are base64url JSON binding project_id, revision, operation, query_hash and the composite after key. They are query state, never authorization: decoding validates the binding and raises stale_cursor when it no longer matches. src/core/identity.ts (encodeCursor, decodeCursor).

Content-derived identity

IDs are prefix_ plus 64 hex digits. Image identity is literally the SHA-256 of the file; slice identity is a fingerprint of image id, offset, size and architecture; entity identity is a fingerprint of slice id, kind and an immutable birth discriminator, so a split or merge mints new IDs and records lineage rather than renaming an old one (the comment in entityIdentity says exactly this). Project and job/annotation/evidence/artifact identities are randomly minted when they are not content-derived. Canonical encoding tags every scalar type before hashing, so bigint 1 and the string "0x1" cannot collide. src/core/identity.ts (canonicalIdentity, entityIdentity).

Address spaces

An Address is { image_id, space, value } with space ∈ va, rva, file. File offsets address the immutable container, not the selected slice. AddressMap.translate returns mapped, zero_fill or unmapped, and spans partitions a read without inventing bytes for holes or zero-fill; both refuse a foreign image id. This is the entire reason a memory read can say “zero-filled” instead of returning bytes that were never there. src/core/addresses.ts (AddressMap, Translation). Details on slice selection and per-format mapping live in 02 Loading binaries & addresses.

Limitations & extension points

Global gaps visible in code and tests, plus the roadmap items the repository tracks. Items marked roadmap come from TODO.md and CONTINUE.md and are not current capabilities.

Known gaps

  • Three target triples only. targetSchema rejects every other combination, and pipelineComponents throws unsupported_target. There is no 32-bit, big-endian, ARM64 PE or x86-64 Mach-O path.
  • Discovery is bounded and evidence-based, not exhaustive. FunctionRecord.boundary can be candidate or conflicting, and analysis can be not_analyzed. On the fixture used above, functions reports partial (incomplete_index) even though every listed function is established — the index describes its documented seeded subset, not all code. See 03.
  • Open call interfaces stay open. Unresolved calls retain ... and conservative effects; AbiCallLayout.state can be partial or unsupported. The tool does not guess arity. See 06.
  • Deep provenance can be shed. An artifact larger than 16 MiB first loses its incremental-reuse readset, then whole provenance classes in EMISSION_METADATA_SHED_ORDER; each omission is named in emission.omitted and produces a partial provenance coverage entry. Pseudocode, signature and the annotation catalog are never shed. src/project/cache/index.ts.
  • An output-limit envelope is not a semantic partial. It carries state: 'partial', reason: 'output_limit' and an artifact handle; consumers that only look at state will misread it. See Figure 7.
  • Roadmap: per-slot stack promotion (today an escaped frame address can keep every slot as *(T *)(entry_sp - N)); region-collapse structuring to remove gotos; a unified expression rewrite pool; image-wide pointer inference; and an opt-in likely inference mode. TODO.md labels these R1–R5 and explicitly says they are planned, not current.
  • Roadmap: resumable per-root whole-image discovery, ObjC super/ivar coverage, and additional benchmark binaries (CONTINUE.md).

Adding a new target

The integration seams are ordinary interfaces in src/core/contracts.ts. A new format needs a Loader; a new ISA needs a Decoder and a Lifter<RegisterIR>; a new convention needs an AbiProfile; a new dialect needs an Emitter<Presentation>. Concretely:

  1. Loader. Implement inspect(bytes, imageId, context) and load({ image_id, sha256, bytes, slice_id }, context), returning slices, mappings, symbols, hints, evidence and diagnostics. Give it a stable name/version.
  2. Registration. Extend targetSchema's enums and its format/ISA/ABI refinement, add the pair to components and targetPipeline in src/service/analysis/versions.ts, extend versionRecords, and add the magic sniff in workers/runtime.ts. Update pipelineComponents's error path only if the diagnostic text changes.
  3. Decoder selection. reconstructFunctionGraph and prepareQueryImport choose a decoder by image.target.architecture; a third architecture needs a branch there (and a dispose() call on every path). The decoder's version becomes part of versions.decoder.
  4. Lifter + ABI. Return a RegisterIR with lift coverage and diagnostics; implement classifyCall returning an AbiCallLayout whose state is honest about unsupported aggregates. boundIR and requirePass enforce the rest.
  5. Bump versions. Any semantic change to a stage group must bump its entry in the analysis composition string; otherwise a stale artifact can be reused under the old key. This is the repository's stated cache contract.
Refusal

Until every component exists, the correct behaviour is to throw unsupported_target from pipelineComponents rather than assemble a partial pipeline. The same rule applies per operation: a loader that cannot establish a slice returns ambiguous_slice diagnostics with the candidate list, and a discovery seed that is not an indexed virtual root is invalid_address.
