Where this sits in the pipeline

Stage 09 has two halves that are deliberately kept apart. The first, in src/presentation/index.ts, is a pure graph transformation: structureControlFlow consumes the validated SSAForm produced by SSA, values & stack and returns a StructuredFunction whose body is a tree of blocks, sequences and loops. It knows nothing about C, Python, identifiers or types.

The second half is the renderer in src/emitters/renderer.ts. Its constructor calls reconstruct(input, context, view) from src/reconstruction/index.ts — the stage described in Source reconstruction — and then runs its own presentation planning. render() walks the resulting region tree and writes text through Writer. Both dialect entry points are thin wrappers around the same function: emitC in src/emitters/c/index.ts and emitPythonLike in src/emitters/python-like/index.ts call renderSource with only a different language tag and version string. As the comment on Renderer says, “Only syntax lives here: both dialects consume the same reconstructed program.”

The coordinator is src/service/analysis/index.ts. It recovers types, calls structureControlFlow(ir, context, { max_work: context.budget.work }), escalates a partial structuring through requirePass, and then calls the selected emitter with { function: structured.value, types, names, annotations, source }. The result is an Emission: text plus interned identity, proof and range tables, source mappings, declaration span, helper explanations, local-validation records, inference records and requirement proofs.

Two views

options.view selects 'source' (the default, pretty view) or 'checked' (the unsimplified view). sourceView is simply options.view !== 'checked', and planSourceControl is called only in the source view. The checked view prints the structured body unchanged, with every reduction, helper call and explicit cast spelled out.

The presentation model

StructuredFunction is a Region tree, not a list of basic blocks with edges. A Region is one of three things: a BlockRegion (statements plus one control), a SequenceRegion (an ordered lexical list), or a LoopRegion (a header identity plus a body). Each block's control is a jump, an if, a switch, or one of the original terminal terminators (return, indirect, trap, unknown). Every non-terminal edge is a ParallelTransfer. 

export interface BlockRegion extends Origin {
  readonly kind: 'block';
  readonly parameters: readonly Value[];
  readonly effect_parameter: Effect;
  readonly dominator: EntityId | null;
  readonly register_entry: readonly RegisterBinding[];
  readonly register_exit: readonly RegisterBinding[];
  readonly statements: readonly Instruction[];
  readonly control: Control;
}
export interface SequenceRegion {
  readonly kind: 'sequence';
  readonly regions: readonly Region[];
}
export interface LoopRegion {
  readonly kind: 'loop';
  readonly header: EntityId;
  readonly body: Region;
  readonly form?: LoopForm;
  readonly once?: true;
}

Defined in src/presentation/model.ts (Region, LoopRegion, LoopForm).

ParallelTransfer is the semantic centre of the model. It carries a target block, a mode (goto, next, break, continue), the loop identity a break/continue refers to, the edge copies as destination/source pairs, and the effect transfer. The copies are simultaneous: “All sources are read before any destination is written, including the effect.” This is why a swap of two loop-carried values prints correctly even when it cannot be printed as two sequential assignments.

LoopForm is deliberately absent from the structurer's output. The comment on LoopForm says it is “chosen after reconstruction (never by the structurer)”. Structuring produces a generic loop whose body starts at the header; the renderer's planLoopForms may later prove that the same region can be printed as while, do_while, or for. If no form is chosen, the generic loop prints as while (true) with explicit transfers. A once loop is not a loop at all: it is a block run once, printed as do { … } while (0) in C-like output.

Invariants the renderer relies on

From the structureControlFlow contract: every block label is addressable, including labels nested in arms; a sequence is lexical order and not implicit fallthrough; a loop body starts at the header and repeats only on an explicit continue; break/continue identify both their loop and exact destination/copies; statements retain identity, provenance, effect tokens and boundary snapshots. No untouched CFG is embedded in the output.

Atom
Structuring's intermediate unit: one region plus its owned members and a tail block whose control is the only place a successor can still be absorbed.
Arm body
A region owned by one ControlArm, entered only after that arm's transfer. Its presence is what makes a test own a subtree instead of merely jumping.
Printed copy
An edge copy that actually appears in text after phi/variable coalescing and for-header hoisting. printedCopies is the renderer's single source for these.
Silent block
A block that prints nothing: no retained statement except a promoted flag access or a statement whose result is inlined at its reader, and no source definitions anchored at the block, its control or its statements. Rules that need a genuinely empty block also reject notes and deferred stores. Many layout rules require silence because they move or merge controls.

Structuring the CFG

structureControlFlow is a recursive, budgeted SCC reduction. It takes an SSAForm, an OperationContext and StructuringOptions { max_work?, max_depth? }. max_depth defaults to 32 and must be an integer in 1..64; anything else throws RangeError('Structuring depth must be 1..64'). max_work is passed to AnalysisBudget, whose own default is 1,000,000 work units; the service supplies the operation budget instead.

  1. Index the graph. Every block, parameter, instruction, edge and edge argument is charged to the budget. Predecessor lists and successors are built; register-state rows are keyed by block, and computeDominance records every block's immediate dominator, from which derived register state is read.
  2. Convert edges to transfers. The local transfer helper maps an Edge to a ParallelTransfer. It walks the current loop scopes from innermost outward: an edge to a scope's header is continue; an edge leaving a scope is break; everything else is goto. Edge arguments become copies paired with the target block's parameters; the edge effect becomes the effect transfer.
  3. Find SCCs. The local components function is an iterative Kosaraju traversal (the code says so explicitly: “Iterative Kosaraju avoids call-stack dependence on adversarial CFG size”). Loop headers of the surrounding scopes are suppressed as targets while walking, so a header backedge does not make the parent component cyclic and nested loops become visible. At the depth limit, groups are singleton blocks instead.
  4. Build regions bottom-up. Groups are reduced in reverse order (successors before owners). A group is cyclic when it has more than one member, or when one member has an unsuppressed self-edge. If it is cyclic, has exactly one entry (the function entry or a block with an outside predecessor), and there is depth headroom, it becomes a LoopRegion and is recursively built with a new scope. Otherwise every member becomes a leaf BlockRegion.
  5. Absorb unique-entry successors. The fixpoint loop inspects each atom's tail control. Only a bodyless goto arm is a candidate. The target atom must exist, must not be the current atom, must begin exactly at the transfer target, and must not already contain the current region's entry. The target must have exactly one incoming edge from outside its own members. Under those conditions a jump becomes a next transfer and concatenates a sequence; an if or switch arm owns the target region as its body. The pass repeats until nothing changes.
  6. Order and record coverage. The entry atom's region is emitted first, then the remaining atoms in map order, joined as a sequence. coverage records every original block, its statement ids and its terminator id, including blocks that were unreachable from the entry. 
const cyclic =
  group.length > 1 ||
  edges.get(group[0]!)!.some((edge) => {
    return edge.target === group[0] && !scopes.some((scope) => scope.header === edge.target);
  });
if (depth + 2 < maxDepth && cyclic && entries.size === 1) {
  const header = entries.values().next().value!;
  const body = build(members, header, [...scopes, { header, members }], depth + 2);
  const atom: Atom = {
    entry: header, members, region: { kind: 'loop', header, body }, tail: undefined,
    depth: regionDepth(body) + 1,
  };
  atoms.set(header, atom);
  for (const id of group) owner.set(id, atom);
} else
  for (const id of group) {
    const block = leaf(id, scopes), atom: Atom = { … region: block, tail: block … };
    atoms.set(id, atom); owner.set(id, atom);
  }

Abridged from build in src/presentation/index.ts.

The absorption test is intentionally conservative. It never absorbs an arm that already owns a body, and it never absorbs a break or continue: those transfers carry loop identity and exact destinations that a lexical concatenation would lose. It also enforces a depth estimate before accepting a merge: regionDepth counts loop bodies, sequence nesting and owned arm bodies, and the candidate is skipped when depth + nextDepth >= maxDepth. A deeper shape therefore keeps labelled transfers rather than failing.

Refusal and partial states

Work exhaustion and cancellation are transactional. The outer catch calls budget.result(null, error), yielding { state: 'partial', value: null, diagnostics, work }; it never returns a truncated tree. AnalysisBudget.result rethrows any error that is not an OperationError with code resource_limit or cancelled. The service's requirePass converts such a partial result into an OperationError (and any other partial pass into unavailable_semantics), so no partial pseudocode is published from the native pipeline.

Figure 2 also explains a detail that can look surprising: there is no else in the emitted text even though the tree has a false arm. The arm's body ends in a loop that can fall through, while the true arm returns. sourceIf recognises an arm that cannot fall through (terminates) and prints the other arm at the same indentation after the closing brace. The tree still owns it; the syntax merely omits the redundant else.

The renderer and its phases

new Renderer(input, options, context, language, version, rejectedCalls = new Set(), metadata = 'full') is ordered in four groups.

  1. Reconstruct. reconstruct(input, context, view) validates the structured tree, computes liveness and use counts, rewrites pure expressions, projects ABI boundaries and builds the Reconstruction maps: blocks, values, expressions, inline set, live set, retained statements, transfers, origins, parameters, calls, returns, tails, physical inputs/exits and memory views.
  2. Index and name. The constructor builds origins, statements and controls; it rejects duplicate structured statement or control identities with OperationError('invalid_input'). planSourceNames assigns source-role names and distinguishes loop-carried header phis from initial values. Globals are planned with planGlobals, characters with characterEvidence, and C integer-storage presentation is checked through the local validator.
  3. Plan the source view. Only when sourceView is true, planSourceControl() runs. It is the ordered pipeline described in the next section; its output is a new body: Region plus maps such as variables, flagTests, exitFlags and loopExits. findLabels later adds loopTests and actions.
  4. Prepare printing. findLabels decides the lexical action of every transfer occurrence and records which targets need a label. validateReconstruction checks the program invariants before a byte is written.

render() itself writes in a fixed order: the reconstruction_model helper explanation; the dialect/source comment; FP requirement comments or the compact requirement note; the signature and parameter mappings; stack-frame and local declarations; the body via region(this.body, 1); the closing brace or Python suite check; then deferred insertions. The insertions matter because several preludes depend on the finished body: structure bodies, global declarations, function-pointer typedefs, C scalar-support macros and the ABI-scratch note are inserted at recorded offsets with writer.insertLines, which shifts every mapping at or after the boundary.

Call inlining and the retry

A call with exactly one live result that is read once by the next printed statement (or by the return, if or switch test) is printed as an operand of that reader, at the call's original position. This is not a syntax trick: admitInlinedCall also requires that the printed result type is the result variable's type. The call is held when its block is reached; the text is not emitted yet. When the reader is about to print, reader() checks that no code line was printed in between: 

private reader(print: () => void): void {
  if (this.openReader && this.writer.watched === null) return print();
  this.settleReader();
  const held = [...this.pendingCalls.keys()].map((id) => this.inlinedCalls.get(id)!);
  if (!held.length) return print();
  if (this.writer.codeLines !== this.heldLines)
    throw new CallInliningRetry([...this.pendingCalls.keys()]);
  this.openReader = { start: this.writer.offset, held };
  this.writer.watched = null;
  print();
  this.settleReader();
}

If the assumption was wrong, renderSource adds the failed calls' results to a rejected set and renders again; each retry prints the rejected calls as statements, and after four retries every call is printed as a statement. The outer fallback handles a different limit: if provenance metadata exceeds its bound, MetadataLimitError is thrown, the same text is rendered in metadata: 'omitted' mode, and the emission records the omission. 

export function renderSource(
  input: EmissionInput,
  options: ConstructorParameters<typeof Renderer>[1],
  context: OperationContext,
  language: 'c-like' | 'python-like',
  version: string,
): EmissionResult {
  const attempt = (metadata: 'full' | 'omitted'): EmissionResult => {
    const rejected = new Set<string>();
    // Each retry prints the failed calls as statements.
    for (let retry = 0; ; retry++) {
      try {
        return new Renderer(
          input, options, context, language, version,
          retry < 4 ? rejected : null,
          metadata,
        ).render();
      } catch (error) {
        if (!(error instanceof CallInliningRetry) || retry >= 4) throw error;
        for (const id of error.results) rejected.add(id);
      }
    }
  };
  try {
    return attempt('full');
  } catch (error) {
    if (!(error instanceof MetadataLimitError)) throw error;
    return attempt('omitted');
  }
}

Text is validated, not trusted

Before render() returns, validateRenderedTransfers re-derives every emitted edge from the printed body, and validateEmittedControl checks loop/switch scopes, break/continue targets and exit guards. Every structured coverage entry's block must exist in the reconstruction, and its control and every statement must have been mapped; otherwise invalid_input is thrown. A control-validation record with status rejected is itself rejected through rejectTranslation.

Planning control-flow layout

Source layout is where the printed program is allowed to become more readable than the literal tree, but never more permissive. Every rewrite goes through LocalValidationSession.presentation(rule, subject, scope, subjectIds?). It records a presentation validation record and returns false when its record bound is exhausted; the caller then keeps the explicit form. The pass order in planSourceControl is:

Lexical transfer actions

transferAction(transfer, nesting, destination, language, sourceView, sourceProgram, normalizeLoopTargets) answers one question: does this edge print a goto, a break, a continue, or nothing at all? In the source view, any transfer whose target is already the lexical destination is fallthrough. With normalisation, a transfer to the nearest enclosing loop's header is continue, and a transfer to that loop's follow is break — but only when the follow is actually the loop's lexical successor and, for C, only when no switch intervenes. The renderer computes normalizeLoopTargets by comparing both derivations over every transfer; if any differ, the normalisation is recorded as a presentation rule. If its record cannot be kept, the structurer's annotations win.

visitTransfers supplies the lexical destination and nesting. It treats a sequence as successive lexical entries, a loop body as falling into the loop header, and an owned arm body as falling into the arm's own body (or the shared-arm body for a joins operand). gotoOccurrences is just this walk filtered to actions equal to goto.

Layout: ordering, tails and exits

planLayout is the largest layout pass. Its comments number the steps; the important conditions are:

  • Dependency ordering. Acyclic sibling regions are topologically ordered by their outgoing targets, with a loop header backedge ignored (the enclosing loop performs it). A successor whose external incoming edges all belong to one owned region is moved into the smallest region containing all those edges, after any containing loop. Cycles are not reordered; they retain labels. Newly ready continuations are preferred, so a loop's sole exit lands immediately after it.
  • Exit merging. joinExits first tries the exit reached by strictly most edges of a loop (when at least two reach it) as the loop's lexical successor, so those edges become breaks; otherwise, when some exit is not a duplicable tail, it tries each exit in turn. Every other exit must either be a duplicable tail or a terminal/jump block entered by one edge from inside the loop; that block is embedded at the edge (moved onto the break path). The pass then re-walks the result and requires every edge from the loop or moved blocks to the shared exit to print as break; otherwise the candidate is rejected.
  • Tail duplication. A tail is at most four blocks, each at most four assignments/loads/stores/calls, with at most four printed copies per edge, ending in a return, indirect or trap terminator. A total budget of 128 copied blocks bounds the expansion (budget = 128). A labelled edge into such a tail ends in an owned copy of the tail instead of a label. After duplication, any tail home no longer reachable lexically is pruned; its copies remain.
  • Terminal placement. A terminal block whose only CFG edge is a labelled edge moves onto that edge. A terminal block entered only from inside one loop may move right after that loop when it is the only movable exit and every other exit is a duplicable tail.
  • Forced tails. If the only code lexically between a goto and its target is tail homes, those tails are copied onto every incoming edge, fallthroughs included, so the goto becomes a fallthrough. This is an optional search: it charges at most 1/16 of the remaining work (optionalWork(context, 16)), its total copy cost must be at most 64, and the rewrite is kept only if the number of gotos actually falls.

Optional searches stop at a fixed share of the remaining work, so they cannot starve the emission: planBreakableBlocks and planSharedArms use share 16; coalesceValues uses remainingWork / 8.

Loop forms

planLoopForms only assigns a LoopForm; the region tree keeps every transfer. A form is refused whenever its syntax would move an effect across an observable boundary. The exact gates are:

  • The loop must have a known lexical follow and no entry edge that prints as a goto.
  • while. The header block must print nothing. Its if must be an ordinary condition (facts.plain) and one arm must be a copy-free exit to the follow. Additional tests may chain while each stage is the leading lexical region, single-entry, silent and copy-free on exit, with a copy-free staying arm, and the next lexical region begins at the staying transfer's target. If the chain has more than one test, the whole chain prints as one while (a && b && …).
  • for. In C-like output only, a while-shaped header may become for when exactly one external entry edge falls into the loop, the body's lexical end is the only repeat edge, and facts.induction proves that the entry and repeat copies only initialize and step induction variables (x = x ± c) that nothing else inside the loop writes, with the test reading one of them. A bottom-tested for additionally requires the first test to be implied on entry by an enclosing if guard.
  • do-while. C-like only. The lexically last block must end in an if whose repeat arm is the only continue to the header, and the other arm must be the copy-free exit. Every other entry must fall through from outside. The repeat copies' written variables must not be live at the exit, must not be read by the exit copies, and if the test reads them, restateTest must prove an exact restatement over the pre-copy values.

Breakable blocks, shared arms and switch guards

planBreakableBlocks attacks forward gotos inside one enclosing statement list. For a goto to a later sibling, it wraps the elements from the goto's own index up to (not including) the target in a once loop. It refuses any wrap whose head is already a scope identity (an exit-flag or guard header) or whose body can re-enter the head. The candidate is kept only if the total number of printed gotos decreases; an edge that would newly cross the wrap to an outer loop counts as one. Up to 32 attempts are made, under the shared optional-work allowance.

planSharedArms handles the shape if (a && b) { F } X where every operand's leaving edge reaches X, X is entered by those edges only, and F leaves for the statement after X. Operands must be copy-free tests that the condition can print (silent, no flags, no requirement predicates, no anchored notes/definitions), with at most copy-free silent jumps between them. The chain must contain at least two members and the target's incoming count must equal the number of leaving arms. The rewrite marks the head's arm shared and the other operands' arms joins; the renderer then prints one if (…) with an else for X (form all) or swaps the arms (form any). No statement, copy or effect moves.

foldSwitchGuards is narrower than it looks. A guard if folds into the switch it enters only when the switch's jump_table.exact_guard_instruction names an instruction that the guard's provenance contains; the entering arm is copy-free and targets the switch block exactly; the switch block prints nothing and is otherwise eligible; the switch has no otherwise body; and the guard's other arm goes to the switch's own otherwise target. The switch then prints in the guard's place with that other arm as its default. This is a proof-carrying rewrite, not a heuristic range guess.

Phi copies and variable liveness

VariableLiveness works on the values that will actually be printed as variables. It indexes live values that are not inline-expanded, not single-use calls and not stack-address values, plus every formal. Its bit-set summary per block is built from ordered events: uses before definitions, definitions as events, and reads from control conditions, returns, physical exits, tail boundaries and edge copies. Liveness is solved by a backward fixed point over successors, removing a successor's bound parameters at the edge. It is monotone over a finite lattice; if it needs more than blocks.length + 2 rounds it throws Error('Liveness did not converge'). The analysis marks itself incomplete when there are more than 4096 values or blocks, and coalescing then returns nothing.

coalescePhiCopies builds an interference graph:

  1. Candidate pairs come from every reconstructed transfer's copies plus the renderer's widening assignments. Both endpoints must be indexed, compatible, and the source must not be an inline value.
  2. Each block is scanned backwards from its exit-live set. A definition kills its destination, then conflicts it with every other value in the same definition event and with every candidate still live. An exception is an equal-value assignment (y = x where the source and destination hold the same value at that definition).
  3. Block parameters and formals are bound simultaneously on entry, so they conflict with each other and with values live at entry.
  4. Candidate classes are joined greedily in pair order. A join is accepted only when no member of one class interferes with any member of the other and every cross pair is compatible. The representative is a formal if the class has one; otherwise the earliest widest declaration.

compatible in the renderer compares storage width and type identity, plus supplied names: machine storage type must match, type ids and printed spellings must match, and any supplied name must agree. Pointer formals can match if the spellings match after dropping a top-level const. If the classes merge, the renderer declares the representative once and prints every member under it. The result is real: the checked view of _fixture_loop has separate accumulator and accumulator_1 values and explicit copies; the source view prints one accumulator.

coalesceValues then handles in-place updates. Candidates are definitions whose last reader is an operand variable, such as y = f(x). Two classes join only if no member of one is live where a member of the other is defined, every member pair is sharedStorage-compatible, and existing phi classes only grow. Unlike coalescePhiCopies, the interference matrix is optional work: the pass spends at most remainingWork / 8. If it cannot afford the matrix, or nothing merged, it returns undefined and the renderer keeps the previous map.

Multi-level loop exits

An irreducible-looking “break out of two loops” is not printed as a goto when the target is an enclosing loop's exact lexical continuation. planLoopExits records a LoopExitRoute for an edge that must cross two or more breakable scopes to reach that continuation. The route names the target loop and every intervening loop or switch. The renderer allocates one uint8_t flag per target loop (loop_exit_N), initialises it before each entry to that loop, sets it on the edge and breaks; immediately after each intervening loop or switch, propagateLoopExit prints if (flag) { break; } before any following effect. Arbitrary target jumps, loop entries and irreducible edges are never rewritten this way.

Expression rendering

SourcePrinter in src/emitters/expressions.ts turns IR expressions into Printed values. A Printed is not just text: 

export interface Printed {
  readonly text: string;
  readonly precedence: number;
  readonly ctype: IntegerCType | null;
  readonly unreduced?: Printed;
  readonly widened?: Printed;
  readonly from?: { readonly operand: Printed; readonly bits: number };
  readonly negated?: Printed;
  readonly pointer?: { readonly text: string; readonly type: string };
}

Those extra fields let later contexts avoid casts without changing semantics: unreduced is the value before its final modular reduction, so a C assignment or return to exactly that unsigned type may print it; widened is the same value at a narrower unsigned type; from remembers the operand of a cast so a second cast that keeps no more bits can collapse; negated makes double negation the identity; pointer lets a pointer context print the declared lvalue instead of an integer round trip.

Precedence and parenthesisation

Both dialects share PRIMARY = 16, UNARY = 14 and CONDITIONAL = 3, but binary precedence differs: C has * / % at 13, + - at 12, shifts at 11, relational at 10, equality at 9, & at 8, ^ at 7 and | at 6; Python places bitwise operators above comparisons. SourcePrinter.binary prints operands with group(value, minimum): 

group(value: Printed, minimum: number): string {
  return value.precedence < minimum ? `(${value.text})` : value.text;
}

It groups more than strict precedence requires. Within a bitwise operator, a lower- precedence operand is parenthesised; shifts are similarly protected; a comparison operand that binds more weakly than a shift is grouped even in C, because compilers warn (-Wparentheses) about mixed comparison and bitwise expressions. In Python, comparisons at the same precedence are also grouped so Python's comparison chaining can never change meaning. Logical connectives are printed by logical: &&/|| in C, and/or in Python, with C's && inside || grouped.

The checked view uses a different printer. Every reduction is spelled with an explicit C cast or a Python-like helper, every compound form is fully parenthesised, and every semantic helper is accompanied by an explanation recorded in Emission.helpers (for example bit_pattern, image_address, uintN, intN). The source view prefers ordinary C operators where the same value is provable.

Casts and conversions

cast(bits, signed, value) returns the value unchanged when its ctype already has that width and signedness. It collapses a reinterpretation of a signed word as unsigned and back into the original typed spelling. It also recurses through widened and from under the conversion_collapse rule: converting to no more bits than an inner conversion already kept needs only the inner operand; a zero extension preserves the value itself, so any outer conversion may start from the narrow operand. Python-like signed formals are the exception: int32(uint32(x)) is retained because the signed spelling is carrying the bit pattern, not merely a conversion.

usualArithmetic and promote model C integer promotions for choosing result types; they are not inferred source types. By contrast, machineType is the storage spelling (bits32_t, ieee64_t, vector_f32x4_t) used when no source type is proven.

Single-use expansion

planSourceInlining (src/emitters/source-inlining.ts) decides which values are not printed as variables. Its gates are semantic, not cosmetic:

Kind Required evidence
Pure integer/IEEE definition Exactly one recorded use, integer or float scalar type, not preserved, not already inline. Recursively scalar operands only.
FP-environment-dependent value Same as above, plus no call, unknown effect or register write on any path from definition to the final use without re-executing it. The scan stops at 128 levels; the reach walk stops after 65536 blocks.
Nonvolatile load Integer result of 8/16/32/64 bits, one use, source reconstruction present, unconditional same-block use after the load, and every intervening statement is an assign, a nested dependency, or a private-local access. Independent potentially faulting loads never become unsequenced operands.
Plain copy propagation Multiple uses of a copy whose expression is just a same-presented-type variable. Every reader prints the source; phi coalescing and liveness treat each read as a read of the source, so storage cannot change in between.
Private-local reuse A load of a private local with exactly two same-block readers; the intervening write is a pure function of the loaded value alone, has no register input, and writes only that local. The write either follows both readers or is printed right after the later reader.
Single-use call One live result, read once unconditionally by the next printed statement or return; no other memory read/call/FP-environment read in the reader; non-result clobbers print nothing; printed result type equals the variable's type.

A propagated copy is not free: the renderer records copy_propagation with every propagated site, and if the record cannot be kept it removes those sites and the call-inlining candidates that depend on them. The same pattern applies to local_load_reuse, single_use_inlining and single_use_call_inlining.

Declarations and evidence-driven spellings

Unsigned bounds and flag tests

UnsignedBounds (src/emitters/source-bounds.ts) derives an inclusive unsigned upper bound from immutable definitions only: constants, masks, zero extensions, truncations, logical right shifts, remainders, and bounded sums or products that cannot wrap. A parameter, phi or load is bounded by its width. The recursion stops at depth 24. The result is used to elide a mask that covers every possible bit and to treat a masked shift count as an ordinary C shift, never to assert a value.

planFlagTests (src/emitters/source-flags.ts) recognises a typical -O0 short circuit. Every flag is a promoted private local whose retained accesses are exactly its chain's zero/one stores and one load; every stage store is the last retained statement of its block; stage blocks are entered only through the chain and the merge only from it; all edges are copy-free; the merge prints only its test, which reads only the flag and is the exact one-bit test over 0 and 1. The chain is limited to MAX_STAGES = 64 and nesting to MAX_NESTING = 8. Later stage blocks print nothing, and the dead flag storage disappears from the declarations.

Literals and character spellings

A pointer-width constant is printed as a string literal only when source evidence establishes an immutable NUL-terminated string with a known encoding at that address; an interior address denotes its suffix. The scope named in STRING_LITERAL_SCOPE limits this to values (argument, store, return, copy, select arm, identity comparison), never arbitrary arithmetic. stringLiteral shows at most STRING_LITERAL_LIMIT = 200 characters and reports the omitted byte count separately. Escaping is dialect-specific and defensive: controls, format/bidi controls, line/paragraph separators, private-use and unassigned code points are escaped; C avoids trigraphs (??x) with \? and comment terminators (*/) with \057; Python uses \u/\U.

Character literals require more evidence than a small integer. characterEvidence marks a value as a character code only when it is a byte loaded through a proven byte pointer (an inferred byte-pointer formal, a typed value, a library char * parameter or result), possibly widened or narrowed losslessly. Even then, characterLiteral prints a character constant only for printable ASCII or (where escapes is allowed) NUL and standard C escapes. Python has no character type, so it prints ord('a').

Globals, tables, structures and local pointers

planGlobals (src/emitters/source-globals.ts) binds retained scalar memory accesses to the object they touch. An object is scalar (one element at offset 0), array (unbounded elements of one scalar type) or bytes (every access an explicit cast dereference). The shape follows only the accesses observed in this function; the extent stays unknown unless the image established one, and a use never invents an array bound. Import slots are folded into the imported symbol's address where the ABI makes that exact.

indexedDataAccesses (src/emitters/source-tables.ts) recognises an exact mapped data base plus nonwrapping integer index arithmetic. Each term is index × stride; masks, zero extensions and dominating comparisons bound the largest index (last). declareDataTables then emits one declaration per (object, element width). A read-only table whose bytes and extent are established prints its contents in full up to TABLE_FULL_BYTES = 512 bytes; larger tables show a TABLE_PREFIX_BYTES = 256 prefix, and an unsized table with unbounded indices shows its first TABLE_UNKNOWN_ELEMENTS = 16 elements. Otherwise it stays an extern view of unknown extent, never an allocation.

SourceStructs (src/emitters/source-structs.ts) synthesises member names from byte offsets in unambiguous hexadecimal (field_0x1d, pad_0x0). layout accepts only an established, asserted or analysis-candidate structure with 1..64 fields, a storage type for every field and no scalar view; members are emitted only for the offsets this function actually accesses. It never claims an array bound or a sizeof that the image did not establish. A one-field structure may print as a scalar pointer when the stride and nested pointee chain prove it.

planLocalTypes (src/emitters/source-local-types.ts) chooses pointer types for connected sets of locals from every definition and use: typed call parameters, typed globals, slots and results, identity tests, dereferences. A set keeps its integer declaration when pointee types conflict, a member is scalar-typed, or the integer conversions it would need cost more than the typed uses it saves. The choice never changes semantics: every needed conversion is still printed, so a pointer read as an integer is (uintptr_t)p.

The C scalar-support prelude is computed from the finished text rather than planned in advance. cScalarSupport scans code only (comments and literals are stripped), then emits only the #includes, wide-integer defines and helper functions/macros the text actually references, in a fixed order. The real fixture_loop output shows an indirect consequence: the word true in while (true) causes #include <stdbool.h>.

Objective-C presentation

Objective-C is not a third emitter. It is a presentation of C-like or Python-like output when input.source.objc is present. The function header becomes the method record, not the symbol: 

-[Class selector]
+[Class selector]        /* class methods */

render() takes method.selector and method.owner from input.source.objc.method, checks the selector against OBJC_SELECTOR, and names the first two integer argument registers self and _cmd. Python-like heads the function with Owner.selector_with_underscores and adds @classmethod for class methods.

At expression level (src/emitters/objc.ts), a 64-bit load from a compiler-emitted selector or class-reference slot prints as @selector(name) or [Name class] in C-like output; Python-like uses the selector(...) / objc_class(...) helpers or the bare class name. A call whose projected arguments match the selector's keyword count (with a known variadic tail after them) prints as a message send: 

/* C-like */
[receiver doThing:first with:second]

# Python-like
receiver.doThing_with(first, second)

Objective-C string constants print as @"text" in C-like and NSString("text") in Python-like, using the same escaping discipline as ordinary literals. All of this requires runtime metadata: without source.objc.messages, an indirect call remains a function-pointer call with an opaque interface.

A real function end to end

The fixture source is fixtures/source/corpus.c; the binary is fixtures/bin/macho-arm64-symbols at VA 0x100000594. The original C is: 

API NOINLINE u32 fixture_loop(const u32 *p, u32 n) {
    u32 result = 0;
    for (u32 i = 0; i < n; ++i) result += p[i];
    return result;
}

The actual default emission (source view, C-like) is:

/* C-like */
#include <stdbool.h>
uint32_t fixture_loop(const uint32_t* address, uint32_t count) {
  uint32_t accumulator;
  uint64_t remaining;
  if (count == 0) {
    return 0;
  }
  accumulator = 0;
  remaining = count;
  while (true) {
    accumulator = *address + accumulator;
    if (remaining == 1) {
      break;
    }
    address = address + 1;
    remaining = (uint32_t)(remaining - 1);
  }
  return accumulator;
}

Command used (--cache keeps the project directory out of fixtures/bin/): 

node dist/src/cli/entry.js decompile fixtures/bin/macho-arm64-symbols \
  --function _fixture_loop --cache /tmp/od-cache

The mapping for that last line is a concrete look at the provenance model. The checked view of the same function is the “before” side of Figures 4 and 5: it prints element, accumulator_1, the explicit backedge copies and the continue/break pair, with every cast and memory view spelled out. Comparing the two outputs is the clearest way to see which constructs are analysis facts and which are presentation: the loop-form choice and the coalescing before/after are separate decisions over the same reconstruction.

Writer, mappings, evidence and limits

Writer (src/emitters/writer.ts) is an append-only UTF-16 text buffer with three interned tables: ids, evidence (called proofs internally) and ranges. Every identity, proof and binary range is stated once; mappings cite them by index. The text offset is measured in UTF-16 code units, matching span_unit: 'utf16'. Resource accounting uses UTF-8 byte lengths, a deliberately different unit.

line(depth, text, code = true) refuses nesting deeper than 256, charges the indentation and text bytes, appends to the part list and advances the offset; statement adds a semicolon only in C-like output; declaration swaps the type/name order by dialect; comment uses /* … */ or # …. insertLines inserts whole depth-0 lines at a recorded line boundary, shifts every mapping at or after it, and refuses an offset that splits a mapping. This is how preludes can depend on the final body without invalidating spans.

Renderer.mapped and Renderer.map populate mappings at every printed statement and control. They add the origin id, every contributor recorded in program.origins, the semantic ids from semanticIds, type ids and their evidence, and data-object evidence. The writer adds origin.provenance.instruction_ids, ranges and evidence, and records semantic_refs with the mapped origin first. Coverage counts how many statements and controls were actually mapped; render() refuses to return if any structured coverage entry is missing.

local_validation is the audit trail of presentation rules. Each LocalValidationRecord is a bitvector, parallel-copy, stack-promotion, control or presentation record with status verified, unverified or rejected. The real fixture_loop emission includes verified single_use_inlining, phi_copy_coalescing and loop_exit_layout records, plus independent bitvector and parallel-copy checks.

The wire form is defined by emissionSchema in src/core/tools.ts and encoded by encodeEmission in src/core/serialization.ts. encodeEmission only converts ranges to their hex wire form; expandEmission resolves every reference and is a view — “nothing is added, dropped or reordered”. The schema enforces that ranges are duplicate-free, that every ref is inside its table, and that no mapping or declaration span exceeds the text.

If provenance exceeds the byte budget, Writer.metadata throws MetadataLimitError. renderSource then re-renders the same text with metadata omitted and records omitted entries for mappings, inferences and requirements. The text is complete and identical; provenanceCoverage reports the layer as partial. Text overflow, by contrast, is a hard resource_limit failure.

MAX_RESULT_DIAGNOSTICS bounds the wire diagnostic list. The renderer keeps at most 999 records and replaces the rest with one omittedDiagnosticsSummary; the summary uses code unavailable_semantics if any semantic limitation was among the shed records, so a truncated list can never look cleaner than the truth. A single diagnostic's evidence list is also capped at 1,000 citations, with the surplus counted in the summary.

Limitations & extension points

What the structurer does not do

The current algorithm is an SCC/unique-entry reduction, not a global region collapse. A cyclic SCC with more than one entry, an irreducible cycle, or a shared join that does not satisfy the single-incoming-edge test keeps labelled transfers. That is deliberate correctness: every edge and every copy remains representable. The visible cost is goto density on adversarial reducible graphs and on some switch/loop combinations.

Later passes reduce the number of gotos without changing the structurer: bounded return tail duplication, terminal-block placement, loop-exit merging, goto-path tail duplication, do { } while (0) wraps for forward gotos, and boolean exit flags for multi-level breaks. Each rewrite is gated by a presentation record and re-checked by the control validators; the optional searches (goto-path tails, breakable blocks, shared arms and in-place coalescing) run under a bounded share of the remaining work. The roadmap in TODO.md (R2, “Region-collapse structuring”) plans to replace the SCC/unique-entry structurer with an iterative collapse over the whole CFG: sequence, if-then, if-then-else, short-circuit &&/||, while/do-while/infinite loops with break/continue, and switch; when no rule applies, pick the goto edge that unblocks the most collapses. It also plans to recover loop forms from the collapsed regions and delete the repair passes the new structurer makes redundant, including tail duplication, forced tail copies, do{}while(0) wraps and loop_exit_layout.

Loop-form recovery is intentionally conservative. The real fixture_loop output is while (true) rather than a for or a bottom-tested while because its header prints before its test, and the bottom-test side conditions are not all met; the original source's for is not recoverable by the current proof rules. This is visible in the output, not hidden.

Switches are only those already established in the IR. The structurer does not build a switch from an if-chain, and guard folding requires the jump_table.exact_guard_instruction proof produced during discovery. The layout pass groups copy-free case arms that share a body and omits an empty default, but it will not invent case ranges or a default target.

What the renderer refuses to simplify

Every source-view rewrite is gated by LocalValidationSession.presentation. If the record bound is exhausted, the call returns false and the caller keeps the explicit form. Optional-work searches also stop at their share: planBreakableBlocks keeps the wraps found so far, while the forced-tail, shared-arm and value-coalescing searches discard their partial result. The renderer never edits emitted text with regexes and never special-cases fixtures. Its repairs are retries: a CallInliningRetry re-renders with the failed calls printed as statements (up to four attempts, then every call), and a MetadataLimitError re-renders the same text with metadata omitted.

Remaining readability costs are known and measurable: open arities (...), integer addresses with casts where pointer evidence is insufficient, frame memory that could not be promoted per slot, extra temporaries that failed the single-use gates, and helper preludes for exact bit-vector semantics. TODO.md tracks these as R1, R3, R4 and R5. None of them are patched in the emitter; they are fixed in the owning reconstruction, analysis or type layer so both dialects benefit.

Emission limits are hard limits, not target sizes. A function whose text exceeds output_bytes fails with resource_limit rather than being truncated. Provenance has its own budget and its own graceful degradation. The maximum structurer depth is 64, the maximum renderer nesting is 128 for label planning and 256 for line writing, and liveness/coalescing turn themselves off rather than approximate when their tables would exceed 4096 values or blocks.

Adding an emitter dialect

A new dialect is a syntax layer over the same reconstruction, but it is not just a new class. The steps, in the order the types force them:

  1. Extend the language unions. Emission.language and analysisOptionsSchema.emitter are currently 'c-like' | 'python-like' in src/core/contracts.ts and the emissionSchema/analysisOptionsSchema in src/core/tools.ts and src/core/primitives.ts. Renderer, Writer, SourcePrinter, transferAction, sourceIf and sourceSwitch all branch on the union, so each branch needs a deliberate decision.
  2. Implement Emitter<EmissionInput> with a stable id, name, version and language, and an emit that returns renderSource(input, options, context, language, version).emission. Follow src/emitters/python-like/index.ts; it is 31 lines because everything substantial is shared.
  3. Register the version in src/service/analysis/versions.ts and add the selection branch in src/service/analysis/index.ts, which today is a binary options.emitter === 'python-like' ? … : …. Update the CLI/MCP option schema and documentation at the same time; the cache identity includes the emitter version.
  4. Add dialect tests at the same level as test/emitters/c: render the shared reconstruction and assert the syntax, not a second analysis. If the dialect changes control syntax, exercise validateRenderedTransfers and validateEmittedControl; they are dialect-aware and reject a spelling whose scopes do not match the emitted edges.

Objective-C demonstrates a cheaper extension pattern: presentation metadata (input.source.objc) changes headers, literals and call spelling without touching control-flow structure or the region tree. If a new syntax can be expressed that way, prefer it over a third full dialect; if it cannot spell the same transfers correctly, do not ship it, because a prettier program that misplaces an edge is worse than a labelled one.

Roadmap labels are plans, not capabilities

The R1–R5 items in TODO.md are explicitly “planned items, not current capabilities”. This page describes the code as it stands: region-collapse structuring, per-slot stack promotion, the larger expression rule pool and opt-in inference are not implemented yet.
