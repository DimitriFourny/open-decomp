# x86-64 decoder

`X86Decoder` implements the core `Decoder` contract using the pinned official
`iced-x86@1.21.0` Node/WASM package. There is no native addon and no assembly-text
semantic input. Import it from `src/decoders/x86_64/index.ts` (use `.js` in TS
imports). `new X86Decoder({ formatting: false })` avoids presentation work;
formatting-enabled instances provide Intel syntax through `format()` for their
own successfully decoded instruction objects. Presentation strings have weak
ownership and are never parsed back into operands.

## Coordinates and bounds

Requests accept VA, RVA, or backed container-file ranges. They are canonicalized
to VA, sorted, and merged before decoding; overlapping requested ranges do not
produce duplicate instructions. Instruction/flow/relative-memory addresses are
static VAs. Ordinary instruction byte references use container-file ranges. If an
instruction crosses adjacent VA mappings with noncontiguous file backing, its
byte reference is instead an explicit VA range: no contiguous file range is
invented. Decoding gathers those mappings across the boundary, never across a
hole, zero-fill, or loader data hint.

The input copy supplied to WASM is bounded to 64 KiB plus the 14-byte maximum
instruction lookahead. Instruction objects are overwritten through `decodeOut`.
Every request charges the shared operation context and checks cancellation.
Instruction-budget exhaustion preserves undecoded backed ranges as `budget`
gaps; context work/deadline/cancellation errors propagate after cleanup. Known
data produces `data` gaps, holes/virtual zero-fill produce `unmapped` gaps, and a
short final encoding produces a `truncated` gap. Invalid encodings remain invalid
instructions with null payload and unknown flow, never proven traps. Actual UD
instructions have trap flow. Linear bounded region decoding does not claim to
perform function discovery; consumers traverse the shared `DecodedFlow` union.

Fully checked loader data ranges are indexed once per immutable `LoadedImage`
object and retained in a decoder-owned `WeakMap`. Preparation is charged to the
original cumulative operation context; failed or cancelled preparation is never
cached. Requests still normalize their own windows, visit relevant data/backing
boundaries, and enforce current work/instruction/cancellation limits. Another
snapshot with the same content hash does not share the prepared metadata.
`dispose()` drops the preparation cache as well as formatter ownership.

## Metadata conventions

- `encoding` is the exact structured opcode variant, not merely the mnemonic.
  Register/operand identities contain no iced numeric enum values.
- `prefixes.bytes` contains the encoded prefix bytes in order, including
  duplicates/ignored legacy prefixes and VEX/EVEX/XOP/MVEX bytes. Effective REX is
  null if a later legacy prefix invalidates its position. Effective semantic
  lock/repeat/segment/mask/rounding fields remain separate.
- Registers use ISA-qualified names and root slices. EAX writes zero-extend RAX;
  AH has offset 8 and preserves the rest of RAX. Legacy XMM writes preserve upper
  vector bits; VEX/EVEX vector writes carry the root zero-extension rule.
- Explicit operands preserve access direction and immediate encoded/effective
  widths. `encoded_bits: 0` distinguishes implied constants such as shift-by-one
  from an actual encoded immediate byte. Sign-extended immediate values are
  unsigned effective-width machine bits. Relative operands preserve the signed
  encoded displacement and target.
- `memory` describes accessed locations, including implicit stack/string effects;
  explicit operands also retain address-only expressions such as LEA. An
  `access_bits` value of zero means address-only, unknown, or variable-sized, not
  a fabricated one-byte access. `operand_bits` zero means no known operand-size
  class; it is not the size of a whole state-save block.
- `flags` uses actual architectural RFLAGS positions (CF 0, PF 2, AF 4, ZF 6,
  SF 7, IF 9, DF 10, OF 11, AC 18, UIF 25). `preserved` is the complement of
  modified flags within that tracked set, not a claim about reserved bits.
  `fpu_flags` is separate: actual x87 status-word C0 8, C1 9, C2 10, C3 14.
  Null means no applicable x87 condition-code metadata. Native iced flag masks
  are explicitly translated rather than mistaken for architectural bit numbers.
- An empty requested feature list does not restrict decoding. A nonempty list is
  an explicit availability set of the structured CPUID feature names exposed in
  `required_features`; missing requirements mark `feature_disabled` while keeping
  the structured encoding available.

Instruction-info effects are dependency metadata, not lifter semantics. In
particular, decoder-reported aggregate state-save effects and feature metadata do
not constitute a complete semantic implementation of those instructions.

The semantic lifter supports legacy SSE `CVTSI2SS` / `CVTSI2SD` from signed 32/64-bit GPR or memory operands to scalar FP32/FP64. It preserves upper vector bits and integer flags, keeps actual load widths/faults, and retains MXCSR guards and unknown exception-status effects. VEX/EVEX conversion is not supported by this legacy rule. The decoder's recognition of other conversion encodings is not semantic support.

The lifter also supports these families, each checked against the Intel SDM definitions (flags included) by interpreter tests in `test/lifters/x86_64/`:

- `BT`/`BTS`/`BTR`/`BTC r/m16/32/64`: CF takes the selected bit, which BTS sets, BTR clears and BTC complements (BT writes nothing); OF/SF/AF/PF are undefined and ZF is unchanged. A register or immediate offset selects bit `offset mod width`. A memory operand with a register offset is the architectural signed bit string: the access is the operand-width word at `address + floor(offset / width) * width / 8`, bit `offset mod width` (tested against a byte-granular bit-string model, including negative offsets); that sub-form under a 32-bit address size stays an unknown effect.
- `BSF`/`BSR`: a zero source sets ZF and leaves the destination `undefined` (the Intel definition; AMD documents it unchanged), including the upper half of a 32-bit destination's root; CF/OF/SF/AF/PF are undefined. `TZCNT`/`LZCNT` are lifted as the BMI1/LZCNT instructions the decoder reports (processors without those features execute the same bytes as `BSF`/`BSR`; the decoder's feature model decides, as for every feature-gated encoding): the operand width for a zero source, CF = zero source, ZF = zero result, OF/SF/AF/PF undefined. `POPCNT` clears CF/OF/SF/AF/PF and sets ZF for a zero source.
- `SHLD`/`SHRD` (immediate or CL count, register or memory destination): the count is masked to 5 (6 for 64-bit) bits; a zero count changes nothing; CF is the last bit shifted out, OF is defined for a count of one only, AF is undefined; a 16-bit count above 16 leaves the result and all flags undefined.
- `LOCK` read-modify-writes (`ADD ADC AND BTC BTR BTS CMPXCHG DEC INC NEG NOT OR SBB SUB XADD XCHG XOR` with a memory destination) and `XCHG` with memory (always locked) are the plain operation between two `memory_fence` events. That is exact for a single-threaded reading and keeps the ordering locked instructions impose on earlier and later accesses; the IR does not express the atomicity of the read-modify-write itself. `CMPXCHG` is lifted for memory destinations (the destination is always written, with its old value on failure; the accumulator is written, a 32-bit one zero-extending RAX, only on failure), `XADD` in all forms. `MFENCE`/`LFENCE`/`SFENCE` are `memory_fence` events (the node's ordering is a lower bound of what they guarantee) and `PAUSE` is a no-op. `CMPXCHG8B`/`CMPXCHG16B`, a register-destination `CMPXCHG` and other `LOCK` forms stay unknown effects.
- Legacy SSE integer: `PUNPCKL/H{BW,WD,DQ,QDQ}`, `UNPCKL/H{PS,PD}`, `PSHUFD`/`PSHUFLW`/`PSHUFHW`/`SHUFPS`/`SHUFPD`, `PCMPEQ{B,W,D,Q}`/`PCMPGT{B,W,D,Q}` (lane masks; `pcmpeq x, x` is all ones), `PMAX`/`PMIN{S,U}{B,W,D}`, `PMOVMSKB`/`MOVMSKPS`/`MOVMSKPD` (zero-extended into the GPR), `PINSRW`/`PEXTRW` (lane `imm & 7`), `PSLL`/`PSRL{W,D,Q}` and `PSRA{W,D}` by immediate or XMM/m128 count (the 64-bit count clamps at the lane width: logical lanes clear, arithmetic lanes fill with the sign), `PSLLDQ`/`PSRLDQ` (byte counts above 15 clear), `PMULUDQ`, `PMULLW`, `PACKSSWB`/`PACKSSDW`/`PACKUSWB`/`PACKUSDW` (signed lanes saturated to half width, destination lanes first), `MOVHPS`/`MOVHPD`/`MOVLPS`/`MOVLPD` (to and from m64) and `MOVHLPS`/`MOVLHPS`. Bits above 127 are preserved; m128 sources require 16-byte alignment (a misaligned access is an oracle fault), m64 half moves do not.
- SSE FP, behind the MXCSR guard and with the canonical-NaN and exception-status abstraction of the other FP operations: `CVTTSS2SI`/`CVTTSD2SI` (truncation; NaN and out-of-range sources give the integer indefinite value, only the sign bit set), `CVTSS2SD`/`CVTSD2SS`, the packed `CVTTPD2DQ`/`CVTTPS2DQ`/`CVTDQ2PD`/`CVTDQ2PS`/`CVTPS2PD`/`CVTPD2PS` (narrowing forms zero the upper quadword), `SQRTSS`/`SQRTSD`, `MIN`/`MAX{SS,SD,PS,PD}` (the second operand's bits, exactly, for NaN or equal operands) and `CMP{SS,SD,PS,PD}` predicates 0-7.

The MMX and VEX/EVEX forms of all of the above stay unknown effects. Rounding FP-to-integer conversions (`CVTSD2SI`, `CVTPD2DQ`...), saturating arithmetic, string operations (including `REP STOS`/`REP MOVS`) and x87 are not lifted.

An unsupported instruction emits one `unknown_effect`, a diagnostic and a coverage reason, and lifting continues with the next instruction when its flow is plain fallthrough or a returning call, exactly as the ARM64 lifter does; a branch, return, trap or unknown-flow instruction that cannot be modeled still ends the block with an `unknown` terminator. When the instruction is valid, unprivileged and falls through, the effect is bounded by the decoder's access sets (`boundedUnknownClobbers`): it clobbers only the register roots it may write (a 32-bit or VEX write clobbers the whole root; a write that preserves the rest of its root, only its slice), the six modeled flags its flag sets say it may modify, MXCSR exception status `[0:6]` when it names an XMM/YMM/ZMM register, and memory `unknown_read_write` only if it may write memory. RSP, callee-saved registers and the MXCSR control bits survive unless the instruction writes them, so the frame, the arguments and the FP-environment presentation are kept across, for example, `rep stosq` (which clobbers RCX, RDI and memory) or an x87 load. An effect that reads a general-purpose register but writes no memory gets memory `read_only` instead of `none`: the IR does not record which inputs an effect depends on, so a frame address read from a GPR keeps the conservative frame-escape treatment; `none` is left for effects whose inputs are vector, flag or unmodeled x87/MMX state (the ARM64 rule). x87, MMX and mask registers are not modeled state and are never outputs. Segment-register writes (which reload the modeled FS/GS base; the `MOV`/`POP` forms are no longer lifted as plain moves), `WRFSBASE`/`WRGSBASE`, MXCSR loads (`LDMXCSR`, `FXRSTOR`, `XRSTOR*`), privileged instructions and every non-sequential flow keep the whole-state clobber of every modeled register, flag and memory.

Interface inference treats the lifter's exact MXCSR guard failure (an effect-free unknown exit taken when the entry/call `MXCSR[6:16]` state differs from `0x7e`: all exceptions masked, DAZ/FTZ off, round to nearest) like the ARM64 FPCR guard failure: it is conditional on the recorded `fp_environment` requirement and does not by itself make a callee's argument list ambiguous. Any other comparison, failure effect or computed control state keeps the unknown exit authoritative. A spilled argument register that only a computed-address stack read (for example through a `va_list`) can observe keeps the observed argument list open rather than closing it without that register.

## Ownership

No WASM-owned instruction, info, opcode, constant-offset, used-register, or
used-memory wrapper escapes adaptation. Per-request instruction/factory objects
are reused and freed in `finally`; each returned info/usage object is freed even
when adaptation throws. Each bounded-buffer decoder is freed on success or
failure. The optional formatter is instance-owned. `dispose()` frees it once,
is idempotent, and makes subsequent `decode`/`format` calls fail explicitly.

## Coordinator verification

With Node 24.22.0 and Bun 1.4.3, first install source dependencies using
`bun install --frozen-lockfile`. These commands exercise the actual adapter
and checked-in compiler-produced PE function bytes, not pre-rendered library output:

```sh
node --import tsx --test --test-name-pattern='PE corpus' test/decoders/x86_64/decoder.test.ts
node --import tsx --test 'test/decoders/x86_64/*.test.ts'
```
