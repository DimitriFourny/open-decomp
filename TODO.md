# Readability roadmap: close the gap with Ghidra

## Goal and rules

Make source-view output read as well as Ghidra's on unseen code without giving up correctness or explicit uncertainty. These are planned items, not current capabilities.

- Correctness before readability. Every rewrite keeps fixed-width arithmetic, signedness, memory/call ordering, aliasing and explicit unknowns. A prettier wrong program is a regression.
- Fix the owning shared layer (IR, analysis, reconstruction, structuring); never repair emitted text with regexes or special-case fixtures or functions. Both dialects consume the same result.
- Reuse the existing local validator (`src/reconstruction/local-validation.ts`), evidence/provenance and cache-version contracts. Bump component versions when output identity changes.
- Tune only on the development loop (`scripts/bench/quality-dev-loop.py`) and our own fixtures. Claims come from a sealed held-out set (see Measurement).

## Baseline (2026-10-19, see docs/PERFORMANCE.md)

On the second held-out suite (8 unseen functions, 24 cells), blind preference was Open Decomp 44, Ghidra 138, tie 10. Ghidra was preferred on every dimension except unresolved semantics; angr was also preferred (84 vs 153). Reviewer reasons: goto labels; integer addresses with casts instead of pointers; frame and unknown-register plumbing; extra temporaries; helper-macro preambles and helper calls (bit-insert, divide-trap, 128-bit). On Ghidra's 16 LLM questions, Open Decomp needs ~2.2× Ghidra's tokens per correct answer. Most of the extra comes from open `...` arities, `entry_sp` frame memory and residual casts.

Root causes found in the code, in the order we plan to address them:

| #   | Gap                                                         | Current mechanism                                                                                                                                                                                                                                              | Ghidra's approach                                                  |
| --- | ----------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| R1  | Frame slots stay `*(T *)(entry_sp - N)`                     | Stack promotion is all-or-nothing per frame: one escaped frame address sets `saveEscaped` and skips every slot (`src/reconstruction/source-stack.ts`, `saveEscaped` and the promotion loops)                                                                   | Per-variable stack recovery                                        |
| R2  | goto labels, cross-loop jumps                               | Cyclic SCCs become loops, unique-entry successors become sequence/if/switch, everything else stays a labeled transfer; bounded repair passes keep a change only if gotos drop (`src/presentation/index.ts`, `src/emitters/source-control.ts` `transferAction`) | Iterative region collapse over the whole graph with goto selection |
| R3  | Extra temporaries, sub-register recombination, helper calls | `simplifySSA` fixpoint with a small rewrite set (`src/analysis/values/index.ts`) plus ~50 named source-view rewrites, each gated by a BDD validator allowance (`src/reconstruction/source-expressions.ts`)                                                     | Large rule pool applied to a fixpoint                              |
| R4  | Integer addresses with casts, `type_N *` names              | IR values are bit-vectors (`src/ir/model.ts`); pointer needs positive local evidence; any conflict drops the source type (`src/reconstruction/source-types.ts`)                                                                                                | Image-wide type propagation during up-front analysis               |
| R5  | Open `...` arities, unknown call interfaces                 | Only proven interfaces close; anything else stays explicit (docs/CORE.md, open-arity section)                                                                                                                                                                  | Guesses prototypes from parameter ID                               |

## R1: Per-slot stack promotion

- [x] Replace the frame-wide `saveEscaped` gate with per-slot escape analysis. A slot is promotable when no escaped address can alias its byte range (derive the range from the escaped pointer's base offset and the observed access extents; unknown extent aliases the whole frame above the base). Keep escaped slots as explicit frame memory; promote the rest.
  - Done in `src/reconstruction/source-stack.ts` (`reachFloor`, requirement `frame_object_base`). No current fact bounds an escaped object's extent, so every escape uses the unknown extent (everything above its lowest offset); optimized frames whose lowest object escapes (SQLite `renameColumnFunc`, brotli `main`) therefore gain nothing. Slots that are not escaped but may be an open-arity call's stack arguments were the main O0 blocker; they now promote above the call's bounded argument area (`open_call_argument_area`).
- [x] Recover each promoted slot's width/type from its accesses and merge split parts (`wide_slot_parts`) per slot, not per frame.
  - Per slot: same-width integer/IEEE puns forward a bitcast, or become one local of the stores' common type whose other-typed accesses print exact reinterpretations (`c_bitcast` / `cast_bitcast`). Narrower integer loads and stores inside a whole-slot integer slot are tracked per byte; loads forward a bit range of one stored value or adjacent stored pieces concatenated. Open: parts whose reaching bytes differ by path (no forwarded value) keep memory form, since a partial update of a scalar local has no exact spelling yet.
- [x] Classify O0 spill/reload pairs of incoming arguments as the argument itself when no intervening write or escape exists.
  - Promoted slots forward through the existing reaching-value analysis; a slot that may be open-call argument storage keeps its stores and forwards reloads with no call, unknown effect or write between (`argument_slot_reload`). A rewritten spill stays a local.
  - Acceptance: on the dev loop and fixtures, O0 cells no longer show `entry_sp - N` for slots whose address never escapes. A slot whose address reaches a call, a store or an unknown effect stays explicit. Executable-subset cases still pass, and the validator rejects nothing new.
  - Dev loop (`base-de95fa4` → `r1-3364fdd`): `entry_sp` 617 → 329 (O0 468 → 208, O2 149 → 121), est. tokens 78,527 → 76,262, casts 3,077 → 2,757. Remaining O0 `entry_sp` without escape: possible open-call argument storage that is never read back after the call (a call result slot reaching the next loop iteration's call in `matrix_callback`; ELF `matrix_variadic_call` argument spills before a variadic call), incoming/aggregate stack bytes, and the SysV `va_list` register save area.

## R2: Region-collapse structuring

- [x] Replace the SCC/unique-entry structurer with an iterative collapse over the whole CFG: sequence, if-then, if-then-else, short-circuit `&&`/`||`, while/do-while/infinite loops with break/continue, and switch. When no rule applies, pick the goto edge that unblocks the most collapses (not the first unmatched edge), then continue.
  - Done in `src/presentation/index.ts` (`structure/4`, see docs/CORE.md). Edge groups into small function tails are labeled first (return splitting); other candidates are simulated (top eight by a one-step lookahead) within a bounded allowance. Short-circuit `||` chains whose then-target is entered by several operand arms still need the source-view `shared_condition_arm` rewrite.
- [x] Recover loop forms from the collapsed regions: `for` from induction variable plus bound plus step when the update is the last statement on the back edge; `do-while` versus `while` from the test position.
  - Loop forms are chosen by `planLoopForms` on the collapsed layout (a loop entered from an `if` arm uses that arm as its `for` guard). The lost `for` loops had two causes: an omitted FP-guard failure block left an empty sequence as the loop body's last statement, hiding the bottom test (`sourceFpPresentation` now drops omitted regions from their list), and in a loop body a branch whose other arm repeats the loop sequenced its exit path after itself, so the repeat edge was not the body's lexical end (the branch now owns a terminal exit path as its arm, `structure/5`). Sample (`scripts/bench/structure-gotos.py`, 214 functions): `for` 0 → 3, the same three as before R2.
- [ ] Keep irreducible graphs correct with explicit labels. Delete the repair passes the new structurer makes redundant (tail duplication, forced tail copies, `do{}while(0)` wraps, `loop_exit_layout`) instead of stacking them on top.
  - Irreducible components loop at their first entry; other entries stay labeled (exit flags refused for such loops). Deleted `loop_exit_layout`, `loop_exit_merge` and `terminal_block_placement`. Tail duplication, forced tail copies and `do{}while(0)` wraps are not redundant: on an intermediate version, removing breakable blocks raised the sample from 458 to 595 gotos and also removing tail copies to 846, so they stay.
  - Acceptance: fewer gotos per function on the dev loop than the current structurer; zero gotos on reducible CFGs without multi-level exits; every reachable edge/effect still represented (existing control-flow invariants); both dialects render the same structure.
  - Goto selection (`structure/5`): candidate labels close the innermost join first (dominator depth of the join's immediate dominator), never orphan a node while another candidate exists, and keep the edge from a join's latest predecessor as its fallthrough. `scripts/bench/structure-gotos.py` (brotli CLI, SQLite `btree`/`vdbemem`/`exprcode`, Mach-O and ELF fixtures; brotli `main` and SQLite `whereLoopAddBtreeIndex` now fail the operation work limit with every build, so they are not counted): on the 213 functions every build prints, gotos pre-R2 196 → `structure/4` 189 → `structure/5` 178. Remaining printed gotos by kind (classified against the printed loop nesting): 156 acyclic within one loop scope, 21 loop exits to a non-follow target, 1 multi-level continue, 1 entry into a loop at its header; zero is not reached: most acyclic ones come from SQLite's own `goto` error paths and jump-threaded joins (a join entered from two arms of different branches), which need a label, a copy or a flag. Still worse than pre-R2: `sqlite3BtreeInsert` 7 → 16, `ParseBase64` 2 → 5, `sqlite3BtreeTripAllCursors` 1 → 3, single gotos in four others; about 54 gotos jump backward (pre-R2 had none), mostly into nodes placed after an unrelated terminal statement (orphan placement) or into arm bodies. Tried and rejected (more gotos on the sample): preferring early-exit "shortcut" edges (209), completing each simulated choice with greedy labeling (allowance exhausted, worse), placing labeled joins only after the region holding all their sources (236). Repair-pass deletion was not measured this round.
  - Result: dev loop 0 → 0 gotos; 215-function sample 409 → 353; property test: 300 random reducible programs with innermost break/continue structure with no labeled transfer; every edge represented exactly once (`test/presentation/support.ts`).

## R3: Expression rule pool

- [x] Introduce a single rule pool over SSA values, applied to a fixpoint with a work bound: constant/identity folding, extension/truncation fusion, sub-register extract/insert recombination into source-width values, shift/mask idioms, comparison/flag canonicalization, strength reduction (multiply/divide by constant, magic-number division to `/` and `%`), and 128-bit multiply-high to `(uint128_t)a * b >> 64`. Move existing scattered `presentation(...)` rewrites into it where they are value rewrites.
  - Done (wt/r3rules): `src/reconstruction/source-rules.ts` is the ordered pool (`EXPRESSION_RULES`, one `ExpressionRule` per rewrite with its proof class), driven to a fixpoint by `normalizeSourceExpressions` with a per-value bound (32 rewrites); the former inline rewrites moved into it. New: `magic_division` (multiply-high and add-back forms, exact closed-form divisor check), `division_narrowing`, `remainder_idiom`, `compare_canonical`, `low_bits_narrowing` as its own lemma. Value-level exact rules (`src/analysis/values/rules.ts`, applied by `simplifySSA`): `zext(trunc v)` is `v` when `v` is bounded, and a reflexive compare of one determinate value is constant (removes x86's unreachable quotient-overflow trap). Done (wt/r3b): signed division in the same recognizer (`exactSignedMagicDivisor`: floor(x·M/2^s) + [x·M < 0] is trunc(x/d) for d = ±ceil(2^s/|M|), checked in closed form on both sides of zero, exhaustive at 8 bits; GCC/clang sign-bit add-back, replicated-sign subtraction and the negated quotient for negative divisors, arm64/x86 at 32/64 bits), signed power-of-two division and remainder (bias select/srl forms, `csneg`, GCC `((x+bias)&m)-bias`; 2^k < 2^(w-1)), remainders over every product spelling (`q - (q << k)`, lea sums), and x86's register-cell spellings of extended operands. Each step tracks the exact integer while it fits and otherwise only its preserved low bits, so the x86 O2 adler32 tail (32-bit add-back over a 64-bit phi) is proven where only those bits are read (`x << 16`): it prints `(uint32_t)(sum2 % 0xfff1) << 16`. The high half of that phi is not provably zero (64-bit loop sums), so no range proof was used. The 128-bit signed product of sign-extended operands prints as `(int128_t)(int64_t)a * b` (`signed_wide_product`); unsigned multiply-high already printed without a temporary once divisions fold. Dev loop (`r3b-base-dc32413` → `r3b-fe33320`): helper preambles 48 → 34, helper calls 46 → 30, casts 2,029 → 1,987, est. tokens 71,638 → 70,838; changed outputs are the x86 O2 `adler32_z` tails (ELF and PE), `matrix_variadic_call` and PE `matrix_mixed`. Open: sign-extended narrow operands whose extension is only implied by the ABI (x86/arm64 `int16_t`/`int8_t` arguments arrive as unextended registers) stay as written; the emitter-level printing simplifications (`redundant_mask`, `negative_addend`, ...) stay in the printer because they depend on printed C types.
- [x] Replace helper calls with plain C where the exact semantics hold under the stated assumptions: bit-field insert/extract to mask-and-shift, division with a proven nonzero divisor to `/`. Keep the helper only when a trap or edge case is actually reachable.
  - Done for division (`native_division`: constant divisor not 0, signed not -1; Python-like signed keeps its helper for operands whose floor division differs) and insert (`mask_insert` printer case). The x86 `matrix_variadic_call` helper came from the source planner inserting the whole IEEE result (not its integer bits) into the unknown ABI overlay; it now inserts the bits view, so the overlay prints as a mask-and-or (the double's bits still need `__od_bitcast_u64_f64`). Variable divisors proven nonzero only by range are not used (no lower-bound facts); a helper stays where a trap or edge case is reachable.
- [x] Copy propagation and temporary elimination at source level: inline single-use pure values when evaluation order and expression size allow it; merge equivalent phi values into one variable.
  - Done (`wt/r3temps`):
    - Single-use call results inline into `if`/`switch` tests, and loads addressed through the call result share the reader (`strerror(*__error())`).
    - Cheap single-reader integer operations repeat at their reader (`repeated_operation`).
    - Phi copies through inline zero extensions share widened unsigned storage (`value0 = ~arg0; value1 = value0` in Mach-O `crc32_z`). This applies only when the extensions are the narrow value's only reads, it is at least `int` wide, and no role name is lost, so no conversion is added.
    - Arms whose blocks print nothing are dropped.
  - Dev loop: 1357 → 1317 local declarations, 8605 → 8504 lines, casts unchanged (3077), no empty arms.
  - Left to other items: pointer/integer copies with different presented types (`address_1`/`address_2`, R4); O0 frame-slot loads, which stay temporaries until promoted (R1). Truncating copies and narrow values read elsewhere stay separate.
- [x] Measure the BDD validator allowance on the dev loop. Raise efficiency (memoize per value, validate rule classes once) rather than silently skipping validation when the allowance runs out.
  - Before: 186 of 200 dev-loop functions exhausted the allowance (1156 candidates not attempted). After: congruence check, most-significant-first BDD order (linear adders), canonical node comparison, shared-subterm leaves with full-cone fallback, a per-session proof-shape cache and an identity fast path for parallel moves: 29 of 200 (459 not attempted), with 6369 bitvector candidates checked instead of 1843. Re-measured after the pool and wt/r3b (JSON `local_validation` records of all 200 dev-loop source decompiles): no function has a `candidates were not attempted` record, at integrate `dc32413` (640 bitvector records) and at wt/r3b (608); exhaustion that skips no later candidate leaves no record and is not counted.
  - Acceptance: the dev loop shows fewer temporaries and no helper preambles for supported idioms. Every rule carries its own bit-precise validation or proof, with counterexample tests at width/sign boundaries.

## R4: Pointer and type inference

- [x] Propagate pointer-ness through the image: a value is a pointer when it is dereferenced, passed where a known prototype expects a pointer, returned from an allocator, compared with a pointer, or derived by add/sub from a pointer. Run this on the callee-summary and image-type paths (`src/service/analysis/image-types.ts`), not only per function.
  - `recoverPointerEvidence` (`src/analysis/types/pointers.ts`) runs after local, callee-summary (`refineMemoryShapes`) and image types, seeded by every pointer association they produced. `applyImageTypes` binds each value of the selected body that flows (argument or result, displacement zero) into an image class some view dereferences to a pointer to that class, so call results and arguments are typed without a callee-summary transfer; a callee doing only integer arithmetic on the parameter confirms no flow (test: `image-types-source.test.ts`). A value passed unchanged where an established prototype expects a pointer confirms its image flow (`ImageTypeObject.declared`), so callers' arguments forwarded through a native callee to e.g. `strrchr` take that declared type; forwarding to an integer parameter confirms nothing. Formals typed by a library declaration print its spelling (`const char* s`, no call-site casts) through the local-type planner; O0 spills reloaded for a call (`argument_slot_reload` / promoted forwards) give the call's declared type to the stored formal (`forwarded_reloads`). Open: with no typed use in the function itself, a declared `char *` prints as `int8_t*` (the library `char` record is shared with `int8_t`); O0 forwarding through a native callee (spill/reload inside the callee) is not followed by image flows. A declared pointer bound to split 32-bit register cells reassembles onto the whole value (narrow `extract`s of one whole as well as `concat` parts) and its exact copies, including `x | 0`/`x + 0`/`x & ~0` moves (AArch64 `mov` is `orr xd, xzr, xn`). Exact copies/phis/selects of one object pointer type keep it (`pointers.ts`), and a declared `void *` call result is refined by that object pointer at its variable.
- [x] Resolve conflicts by evidence weight instead of dropping the type: when one candidate has dereference evidence and the other only an integer use, keep the pointer type and leave a visible cast at the integer use.
- [x] Name recovered structures from their strongest evidence: prototype parameter type, allocator size plus use site, or the field-access pattern shared across functions. Fall back to `type_N` only without any of these.
  - Argument/result roles and shared views name classes; the AAPCS64 hidden-result object gets `<function>_ret`. Allocations: `bun run prototypes` records clang `alloc_size` parameters as catalog `allocates` (curated malloc/calloc/realloc agree with the headers); a call with constant size arguments makes its result a fresh object of that size (`TypeRecoveryResult.allocations`, `MemoryShape.allocation`, structure `size`), named `<function>_alloc_0x<size>` after interface roles and before stack slots. Accesses outside the allocation drop the size claim. A `void *` declaration no longer conflicts with observed accesses as a zero-byte object. Open: the C struct declaration does not print the known size; non-constant sizes (`calloc(n, k)`) stay unnamed by allocation.
- [x] Render pointer arithmetic as indexing or field access when stride and base are established.
  - Element pointers derived by whole-element steps index (`p[k]`), record strides filled by one scalar present as scalar arrays, overlapping views keep the heavier layout so its members render as fields. A member typed integer but accessed as `double` (`matrix_aggregate` +16) is an anonymous union (`union { uint64_t field_0x10; double field_0x10_f; };`, C11 type punning): memory shapes carry one field per access kind (`ObservedField.float`), same-offset same-width members of different kinds never conflict (other overlaps still do), image types merge the two kinds into one layout, and each access prints the member of its own kind without a cast (c-like; python-like prints no structure members, its `memory.u64[...]`/`memory.f64[...]` views are already per kind). Dev loop (`r4c-base` → `r4c-357125a`, only the 13 `matrix_aggregate` texts change): casts 1,961 → 1,905, est. tokens 69,883 → 69,891. Open: the kind of an access is judged from its IR uses (an exact same-width reinterpretation, or a float/vector register binding); a float access whose value also flows through a phi, or whose source-level float closure is rejected, prints through the integer/cast form.
  - Acceptance: on the dev loop, integer-typed locals that are dereferenced become pointers. Struct field access replaces `*(T *)(p + off)` where a layout is recovered. No source type contradicts library prototypes or debug data.

## R5: Inference mode (opt-in guessing)

Guessing may be used only behind an explicit option (`inference: "proven" | "likely"`; CLI `--inference likely`; MCP/API option). It stays off by default until it meets the precision gate, and either way it can always be turned off. Guessed constructs carry a visible marker in both dialects and an inference record in provenance, so they are never mistaken for proven facts.

- [x] Build a precision harness first. Score each heuristic against source-derived ground truth (arity, parameter types, result type, pointer-ness) on our fixtures, the dev loop and SQLite/brotli source. Report precision and coverage per heuristic.
- [x] Caller-consensus arity closure (the design in docs/CORE.md) in likely mode: use the discovered call sites even when the callee is exported or discovery is partial, and close `...` to the arity every caller agrees on.
- [x] Callee arity from the callee's own body: registers read before write that are not callee-saved and not forwarded unchanged into an indirect call.
- [x] Likely pointer and result types from use patterns that R4 rejects as unproven (e.g. a single integer use against several dereferences).
  - Done (`wt/r5b`): R4 leaves no conflicted dereference to rescue (the survey of 120 SQLite functions found no rejected pointer evidence), so the heuristics use what proven analysis never sees: how formals are carried and called through, and what discovered callers do with them. Only `carried_word_formal` passes the 95% gate (25 guesses, 100%, 6.8% coverage); `indirect_call_target` (8 guesses) lacks sites, `opaque_word_formal` is 69-71%, the caller heuristics never fired on the samples (partial caller discovery). No result-type heuristic has measurable coverage: 21 of 24 SQLite pointer results stay integer. Details in docs/PERFORMANCE.md.
- [x] Gate: a heuristic ships in likely mode only at ≥95% precision on the harness. Likely mode becomes the default only if, on the sealed held-out set and the LLM task benchmark, it improves readability and tokens per correct answer without increasing the confident-wrong-answer rate.
  - Acceptance: `proven` mode output is unchanged by this work; the harness reports precision per heuristic; markers and provenance identify every guessed construct.
  - Status: implemented by `scripts/bench/likely-precision.ts` (harness), `src/service/analysis/likely-arity.ts` (`caller_consensus`, `callee_reads` gate), `likely_closure` in `observeParameters`; results in docs/PERFORMANCE.md (both heuristics pass on small samples; consensus coverage on SQLite is zero because its hubs have more than 32 callers or disagreeing prefixes). Open: result types have no passing heuristic; pooled `caller_consensus` measures 86% on the larger corpus, so it is disabled in `LIKELY_GATE` (recorded, not applied); "Likely mode becomes the default" stays unmet (needs the sealed set and the LLM benchmark, not run); indirect-call (callback) arities have no heuristic; "gate" checkbox covers the precision gate only.

## Definition of done for each item

- Define the consumer-visible acceptance criterion or reduce the observed defect to a deterministic behavioral case before implementing.
- Fix the owning shared layer and exercise both dialects through CLI/API/MCP. Delete obsolete passes the change supersedes.
- Run the changed scenario end to end and observe the output. Use semantic regressions for boundaries and effects, not text snapshots.
- Preserve source mappings and provenance; bump cache component versions when output identity changes.
- Update docs (CORE.md, PERFORMANCE.md) only with exercised evidence, including unsupported cases and losses.
